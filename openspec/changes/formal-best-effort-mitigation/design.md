# Design

## Context

现有独立验证器已计算节点供应时长和可选降级指标；实时实验另用未冻结权重排名，父运行只有推荐或负结果。见 proposal.md。

## Goals / Non-Goals

**Goals:** 统一冻结字典序排序、正式部分改善交付、端到端证据和组合搜索。

**Non-Goals:** 不改 Agent 架构，不宣称全局最优或物理无解，不将确定性实验冒充实时模型决策。

## Decisions

- 保留 selected_candidate_id 的推荐语义，RunRecord 新增 mitigation_candidate_id 指向正式挽救；避免现有消费者将选择误解为推荐。
- 基线必须为同任务、相同节点和评估秒数的有效无动作报告。优于基线比较不含候选 ID，并要求逐节点时长改善，显示回退。
- 原生关联有效后才给 Live 正式挽救；缺少关联为 INCOMPLETE。完整推荐优先。
- 墙钟预算耗尽先终止模型及未完成子运行，再汇总已独立验证的结果；保留 BUDGET_EXHAUSTED，交付等级与执行状态独立。原生收尾调用缺失照实记录，不由宿主补造。
- 独立验证器提供全程正常节点数及节点总数；服务层仅对验证报告做差值和排序。
- 组合优先覆盖拓扑靠近故障的多设施组合及备用泵；有限枚举并保留单动作与恢复时序。不扩大冻结权限。
- 用户已确认 15m/75%。新任务在完整门槛不低于此阈值时默认启用；显式 null 停用。自定义或自适应完整门槛低于该值时不自动添加更严格的降级层。历史冻结任务不修改，新实验另存。

## Risks / Trade-offs

交付实验保持原有冻结20m/95%、15m/75%与动作地板。最新+10%复验使用原Live任务及原提交计划，另存物理benchmark证据，不回写已完成Live或冒充原会话原生调用。重复对照使用相同任务、动作域、仿真和墙钟上限；修订消融仅改变冻结修订上限，披露差异。录像保留实际浏览器操作时长并明确完成运行回看。最新源码快照、历史六场景及最新证据分层索引；源代码不携带模型账号、缓存或机器凭据。团队声明、组别、专业与贡献已依据用户确认补齐。用户明确授权GitHub推送与无视频ZIP；保持仓库原可见性，账号、缓存不进入源码、筛选演示数据库或ZIP。视频保持独立任务。

比较页在候选列表前显示当前方案效果摘要，优先展示正常和降级的全程节点数、逐节点等权平均时长占比及最差占比，再显示缺水与剩余违规。改善只与同任务、相同评价窗和节点时长的有效无动作报告比较；降级差值还要求阈值一致。缺失指标显示未提供，不能推断为零。摘要跟随当前候选，并明确正式交付、已推荐或仅候选仿真身份。保留完整违规与逐节点详情。指标描述仿真评估窗口，不声称现场保证或无法完全恢复。

- 组合规模增长 → 生成器按冻结候选预算提前结束，明确有限域。
- 延迟导致无法全程达标 → 保留早期违规并正式呈现挽救价值。
- 历史报告缺少逐节点数据 → 不推断挽救资格；历史结果原样保留。
