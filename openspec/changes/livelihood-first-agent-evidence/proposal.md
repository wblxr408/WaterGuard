# Proposal

## Why

实测显示，现有评测场景里固定顺序枚举已经取到几乎全部收益：Net3 管段123关闭时，111个已测方案中最佳平均达标率仅比固定顺序4次仿真的最佳高0.7个百分点，Net1 的25个有效场景中22个无搜索余量。因此“固定策略更快、质量相同”是必然结果，模型没有被放在真正需要它的位置上。同时降级服务层（15m/75%）只被记录，候选排序仍以正常层指标为准，不优先保住更多节点有水，民生未被兼顾。

## What Changes

- 候选排序改为民生优先：先保关键用水点（若有声明）的应急供水覆盖，再保全网应急覆盖节点数和应急平均达标率，最后才是正常层最差/平均、缺水量和动作成本。可行方案仍必然排在最前。
- 新增可选的民生优先节点声明（医院、学校等，由调度员给定并冻结），验证器输出其应急覆盖指标；未声明时行为不变。
- 固定策略与 Agnes 分工：服务端先给出确定性“先行处置”候选，由 AGH 会话真实提交、仿真、验证；仅当先行处置仍留下民生缺口时才进入 Agnes 精修；缺口为零则不要求模型搜索。
- 诊断工具增加由原始水力结果得到的设施作用证据（流量方向、下游失效节点数及需求占比、是否供给故障点），使精修有固定顺序枚举没有的依据；仍不预测收益。
- 交付结论记录来源（先行处置或 Agnes 精修）及精修相对先行处置的民生增益；增益为零或为负时如实保留先行处置，不宣称 AI 优势。
- 更新 AGH 会话指令、工作流提示与对照实验口径：固定顺序、先行处置、混合三种策略用同冻结任务比较，各自计入实测耗时。
- 按用户最新要求，没有完全达标推荐时，把原生证据完整且已独立验证的最佳候选列为“应急处置推荐（尽力挽救）”。应急推荐是相对已测方案的调度建议，完整恢复状态、剩余供水缺口和扰动状态分别展示；不重跑历史方案。
- 界面与提交材料将低压、供水不足称为“剩余供水缺口”；仅非法操作称为违规。以相对同任务无动作的缺水减少、正常/应急覆盖增加展示挽救收益，完整恢复未达成不否定有效应急推荐。非法动作或无效证据仍不能被包装成推荐。原始机器字段与历史报告保留，不改变验证或选择算法。

## Capabilities

### New Capabilities

- `livelihood-first-dispatch`: 民生优先的候选排序、关键用水点声明及其独立验证指标。
- `first-aid-then-refine`: 固定先行处置加按需 Agnes 精修的工作流、交付来源与增益记录。
- `hydraulic-failure-evidence`: 诊断中基于原始水力结果的设施作用证据。

### Modified Capabilities

无。

## Impact

涉及公共 Schema（任务目标枚举、可选节点声明、验证指标）、验证器与排序、任务提案与默认配置、父运行汇总、工作流提示、诊断、AGH 会话指令、实验脚本及方案对照展示。沿用已有物理仿真、原生关联、独立验证与15m/75%降级阈值；不改变20m/95%推荐门槛、动作时间栅格、权限边界和证据链。
