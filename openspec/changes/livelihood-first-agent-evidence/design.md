# Design

## Context

排序键由 `ranking_key` 按任务冻结的 objectives 计算，现有目标只含正常层指标；降级层指标由验证器输出但不参与排序。固定顺序即 `benchmark_plans` 的拓扑优先枚举，AGH 通过工作流提示和 `wg_diagnose_failure` 得到的设施顺序与其相同。评测数据见 proposal.md：当前场景几乎无搜索余量。

## Goals / Non-Goals

**Goals:** 民生优先的冻结排序；固定先行处置与按需精修的分工；让精修有原始水力依据；如实记录模型增益。

**Non-Goals:** 不改变20m/95%推荐门槛、15m/75%阈值、15分钟动作栅格、权限边界与证据链；不声称全局最优；不预设模型一定优于固定策略；不做自然语言节点解析。

## Decisions

- **目标枚举扩展而非替换。** 新增 `maximize_priority_emergency_coverage`、`maximize_emergency_node_coverage`、`maximize_emergency_mean_availability` 三项。旧目标与旧任务不变。备选“把降级指标并入加权分”被否决：冻结字典序已是项目口径，未冻结权重不可审计。
- **默认顺序由提案服务端组装。** 配置给出完整顺序，`propose_task` 去掉不适用项（无降级层则去掉应急目标，无关键用水点则去掉其目标）。可行方案天然最前，因为通过完整门槛蕴含通过降级门槛。
- **关键用水点是可选冻结输入。** `service_priorities={node_ids, basis}`，校验为用户节点，参与任务哈希。验证器只增加指标，不放宽任何门槛。
- **改善判定计入应急层。** `mitigation_record` 对正常层和应急层分别计算逐节点差值，两层任一有增加且排序更优才算改善；任一层回退都标出。
- **先行处置经 AGH 会话执行。** 工作流提示新增 `first_aid` 阶段，列出由现有枚举按民生顺序截取的候选编号；模型仍通过原生工具提交，保持原生关联。备选“服务端在会话外直接仿真”会破坏原生证据要求，被否决。数量上限为预算份额，并为同方案复验预留一次。
- **精修需求由缺口驱动。** 缺口来自最佳先行处置的独立报告。缺口为零时提示不要求精修，模型调用只用于归档和说明。
- **来源与增益写入父运行汇总。** `delivery_source` 取决于交付候选的计划来源；`refinement_gain` 为精修最佳与先行处置最佳的指标差，未严格更优时为零且来源保持先行处置。
- **应急推荐独立呈现。** 工作区从已保存的原生有效汇总读取完整达标候选，否则读取尽力挽救或最佳已验证候选，增加应急处置推荐字段。界面用该字段标出应急推荐，保留完整达标准入失败及原始违规；用户最新授权此用词，不修改历史selected_candidate_id或重新仿真。
- **设施作用证据来自原始流量。** 读取失败窗口内每条管段的平均有向流量，据此建有向图；对每个设施计算其流向下游可达的失效节点集合及需求占比，并检查能否到达故障点。纯函数，输入拓扑、流量和失效节点，便于独立测试。
- **对照口径。** 固定顺序、先行处置、混合三种策略用同一冻结任务和同一仿真上限，各自按实测决策耗时计入响应延迟下限；报告质量、增益、耗时，三轮以内不做显著性声明。

## Risks / Trade-offs

当前评测场景几乎饱和，混合策略的精修增益很可能为零或很小，此时系统价值体现在速度、民生排序和如实归因，而非模型提升质量；文档与展示不得越出实测。关键用水点由调度员提供，本变更不推断哪些节点是医院。动作栅格为900秒，决策耗时低于约720秒时三种策略的动作下限相同，因此实测延迟差异多数情况下不改变下限。
