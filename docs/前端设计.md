# WaterGuard 前端设计

版本：0.2；日期：2026-10-02；状态：实施设计。本文将二维概念图升级为数据驱动的三维工程管网，并明确 AGH 执行状态、方案证据和治理边界的呈现。配套：[后端设计](后端设计.md)、[Agent 设计](Agent设计.md)。

当前 HTML 是 0.1 历史交互稿，所有拓扑、数值和运行过程均为示意。本次只更新计划与文档，不实现 WebGL、Blender 资产或真实仿真。

## 1 产品定位与设计目标

面向供水故障处置的决策工作台。用户能够回答：哪里发生了问题、哪些节点受影响、当前要求是什么、Agent 做了什么、方案为何通过或被驳回、结论的适用条件是什么。

首页主视觉采用倾斜俯视的三维工程管网；保留二维分析视图用于密集网络和精确比较。聊天输入是任务配置的入口之一，管网、指标和验证结果是主要工作区。

前端不决定方案正确性，不自行生成仿真数字，也不直接调用模型或专业求解工具。用户提交任务后，核心运行进入 AGH，界面读取后端提供的真实状态与证据。

## 2 页面与任务路径

| 页面 | 核心内容 | 主要操作 |
|---|---|---|
| 应急工作台 | 网络、故障、约束、管网状态、当前决策 | 创建任务、回应澄清、启动、取消 |
| 方案比较 | 同条件候选、指标差异、动作与违反项 | 选择候选、定位异常、比较时序 |
| 运行与证据 | AGH 会话、模型、角色、工具、产物关联 | 查看调用、原生记录、下载证据 |
| 评测与回放 | 正常/边界/失败案例与基线实验 | 打开已保存运行，查看评测口径 |

角色架构说明和治理文档放在帮助/项目信息中，不占据实际用户工作台的主导航。原设计稿中的“Agent 架构”等页面是沟通文档，不必原样成为产品功能页。

路径：选择网络及故障 → 填写目标与约束 → 进入 AGH 任务建模 → 必要时回答澄清 → 查看基线与候选 → 查看失败修正与复验 → 比较方案 → 导出证据。

## 3 桌面布局

桌面以约 1440 像素宽作为主要设计基准，三栏宽度可调整：左侧 240–280 像素，中间弹性区域，右侧 300–360 像素。比例是设计起点，不作固定像素依赖。

~~~text
┌─────────────────────────────────────────────────────────────┐
│ WaterGuard  项目/网络  当前任务版本  Live/Replay  AGH运行状态   │
├──────────────┬───────────────────────────┬───────────────────┤
│ 事件与任务    │ 缺供体积 / 关键节点压力     │ 决策与验证记录     │
│ 故障和时间窗  ├───────────────────────────┤ 当前角色与工具     │
│ 目标与硬约束  │                           │ 失败及修正摘要     │
│ 允许操作      │ 三维管网 / 二维分析        │ 证据引用           │
│ 参数来源      │ 选择、定位、剖切、图层     │                   │
│ 澄清与修订    │                           ├───────────────────┤
│              ├───────────────────────────┤ 候选准入状态       │
│ 启动/取消     │ 仿真时间轴 / 曲线 / 候选   │ 已测范围与缺失项   │
└──────────────┴───────────────────────────┴───────────────────┘
~~~

左侧保留有效约束摘要，展开编辑时显示来源、单位及是否影响当前结果。中间最大面积用于空间判断；右侧按决策、动作、工具结果和验证顺序展示事实，不铺满不断滚动的聊天气泡。

1280 像素以下允许右侧切换成抽屉。窄屏优先显示任务摘要、图与结果标签页；触摸端保证选择目标足够大。演示时不依赖复杂拖拽或高精度鼠标操作。

## 4 三维呈现方案

### 4.1 技术与数据分工

建议 React、TypeScript、Vite，Three.js 承担 WebGL 场景；是否采用 React Three Fiber 在首个场景原型验证后决定。二维视图可使用 SVG/Canvas，时序图采用 ECharts。前端共享后端生成的 schema 类型，具体版本在实现阶段锁定。

| 内容 | 生成方式 | 数据依据 |
|---|---|---|
| 管道及连接 | 根据网络数据程序化生成 | 网络连接、路径、管径 |
| 阀门、泵、水箱 | Blender 制作复用资产，导出 GLB/glTF | 设施类型与唯一标识 |
| 道路、建筑与地面 | GIS 或明确标为示意的场景背景 | 坐标与来源资料 |
| 颜色、流向和水位 | 按所选仿真时刻更新 | 实际结果时序 |
| 故障及违规标记 | 程序化覆盖层 | 故障配置、VerificationReport |

避免在 Blender 中手工固定整张管网，否则更换公开网络后需重新制作。每个可交互模型绑定唯一 hydraulic_element_id；渲染网格、标签和碰撞选区可多个对应一个实体，但不能生成新的计算连接。

### 4.2 空间与真实感

- 默认倾斜俯视，提供俯视、故障定位、关键节点定位三个固定镜头。
- 管道使用有体积的几何体，区分主干管与支管，弯头和材质适度体现工程结构。
- 地表透明、地下剖切或分层模式帮助查看埋设管网；不得让建筑长期遮挡核心设施。
- 管径为便于观察可以视觉放大，界面明确标注，属性面板仍显示真实尺寸。
- 不因平滑曲线或优化布局而改变连接关系；交叉但未连接的管道必须可区分。
- 有可信 CRS 时可使用地理底图；只有示意平面坐标时使用工程沙盘，不强行贴到真实城市。
- 节点高程不自动等于管道埋深。缺埋深采用显式示意层，不能声称真实地下还原。

不采用全局自动旋转、持续镜头飞行或遮挡严重的光效。聚焦操作保持方向可预期，用户可立即恢复全图。

### 4.3 水力状态表达

压力和供水比主要在节点上表达，管道流量/流速/状态在边上表达。将节点压力映射成管道颜色时必须说明聚合方式，不能呈现并不存在的沿线压力精度。

流向动画来源于所选时刻的计算流量符号；零流量停止动画。粒子速度若使用视觉缩放须标记为示意，不能冒充真实水体运动。缺失或无效数据使用灰色/斜纹，不插值成正常状态。

数据有时间步长时，播放插值只用于显示，并保留“插值显示”状态。硬约束判定来自服务端原始时间点和配置计算方式，不由动画帧决定。

### 4.4 资产来源

每个外部模型、贴图、图标和底图记录来源 URL、作者、许可、版本、修改情况和署名方式。原创 Blender 文件及导出参数保留。待实现的资产清单放在 data/manifests 或前端 assets 目录旁，不能将下载资产声明为原创。

## 5 AGH 核心流程的可见性

顶部区分：

- Live：本次任务在指定 AGH 中运行，显示可核对的会话与模型信息。
- Replay：回放真实历史记录，显示原始 run_id 和运行时间。
- Fixture：交互设计或开发示意，持续显示标记，不可作为实测证据。
- Benchmark：固定规则或离线对照，不能伪装正式 Agent 运行。

界面展示“AGH 正在调用水力仿真”等状态必须对应真实事件。没有事件时显示等待，不按计时器编造执行步骤。无法关联原生会话时显示“执行来源待核验”，不能使用“AGH 已验证”徽章。

右侧每条工具记录包含角色、工具、开始/结束时间、输入引用、输出摘要、状态及证据入口。摘要描述发生的动作，不显示隐藏思维链。异步计算显示排队/运行/超时，进度无法测量时不用虚假百分比。

## 6 关键交互

### 6.1 任务与澄清

结构化输入包括网络、故障实体、故障类型、作用时间、评估窗口、关键节点、阈值、操作上限。自然语言由 AGH 中的任务建模角色解释。

TaskProposal 中未知或歧义字段需逐项呈现；用户已给清楚的参数不再重复审批。实质改变要求时创建新任务版本，显示差异与受影响的结果。工作台始终可查看原始需求和当前有效配置。

### 6.2 失败定位

点击“关键节点最低压力不满足”后，联动定位节点、最差时刻、压力曲线与阈值来源。动作非法则定位具体设施和被拒参数。数值异常、计算失败、约束违反和证据缺失使用不同文案。

### 6.3 候选比较

选择候选时，地图、指标、曲线、动作、验证和证据一起更新。地图保持同一布局、镜头和颜色标尺。只有网络、任务版本、时间窗口与指标口径相同的候选默认参与排名；不同条件只能在明确标注下查看。

优先显示关键约束满足情况，再展示缺供体积、操作次数和资源开销。不能用综合评分掩盖硬约束违反，不能预先填入未经计算的改善百分比。

### 6.4 回放与取消

仿真时间轴和真实执行时间轴分开命名。回放不产生新调用事件。取消按钮发送幂等请求，状态直到服务器确认后才变为 CANCELLED；保留此前完成的数据。断线显示连接状态，并从 Last-Event-ID 恢复。

## 7 状态与数据绑定

字段和枚举以 [后端公共契约](后端设计.md#4-公共数据契约) 为准。前端主选择状态包含 task_id、revision、run_id、candidate_id、simulation_id、simulation_time_s、selected_element_id、view_mode 和 layer。

推荐准入分五层显示：

~~~text
动作合法 → 仿真有效 → 名义硬约束通过 → 必要扰动复验通过 → 可推荐
~~~

例如名义通过但复验未完成，应显示“名义工况通过，复验待完成”，不能只显示绿色成功。COMPLETED 只是执行结束，必须同时展示 conclusion。BUDGET_EXHAUSTED 仍可展示已验证候选，但注明未完成工作。

事件按 run_id 和 sequence 归并并去重；旧版本结果不能自动替换当前选择。缓存键包括任务、候选、仿真和结果版本，不仅按节点 ID 缓存。

## 9 视觉与性能

采用浅色工程工作台、深墨绿导航。青绿表示满足条件，琥珀表示待处理，红色表示违反；同时使用图形、文字和线型，不能只靠红绿区分。数值使用等宽数字，压力/流量单位紧邻数值。

材质保留体积和明暗，避免反射遮住状态颜色。选中对象有清晰轮廓；悬浮显示简短信息，完整信息在固定面板。图例随着图层变化，管道显示放大、坐标示意等标签始终可见。

首版性能目标在实际展示网络与目标笔记本上测量：交互目标至少 30 FPS，选中反馈目标 100 ms 内，界面更新不阻塞用户取消。这些是验收目标，尚无实测数据。

使用复用资产、实例化、按需标签、LOD 和有限阴影控制负担。资产本地随包提供，避免演示依赖外部 CDN；默认不加载高精度全城模型。WebGL 不可用或性能不足时明确切换二维，保留完整任务与证据功能。

## 10 前端验收

| 验收项 | 标准 |
|---|---|
| 实体一致性 | 可选管段与设备映射到正确水力实体，交叉不误连 |
| 结果联动 | 候选、时刻、指标、曲线、动作和证据一致 |
| 数据缺失 | 无效结果不渲染成正常供水，不产生虚假数字 |
| 来源真实性 | 示意坐标、假设、缩放、外部资产来源可见 |
| AGH 可见性 | 真实事件驱动流程，原生日志可关联 |
| 版本治理 | 修订后旧结果标记过期，不覆盖新任务 |
| 模式隔离 | Live/Replay/Fixture/Benchmark 始终可区分 |
| 恢复取消 | 断线恢复无重复事件，取消以服务端结果为准 |
| 可用性 | 键盘选择、色觉可读、窄屏、二维降级均可用 |
| 性能 | 在实际网络与演示设备上记录测量结果 |

至少用一条真实 AGH 运行验证从任务进入、工具执行、失败修正、结果显示到证据导出的完整路径。当前设计稿的点击演示不能代替这个验收。
