# 物理模型、算法与现实适用性评估

评估日期：2026-10-03；实现：contracts 0.4.0 / PhysicalAdapter 0.4.1，WNTR 1.5.0、EPANET 2.2。依据是当前编译模型、引擎实现、独立物理方程与实际实验。进程治理和代码可靠性另见 [工程审查](仿真工程可靠性审查.md)。

**判断：目前可以完成公开模型上的真实延时水力计算和受约束方案比较，但物理因素并未考虑完全，还不能称为经过现场验证的工业调度模型。水力求解方法成熟；当前固定 A/B 操作策略没有最优性证据。** 本次优化集中在模型参数、内部事件分辨率、物理一致性和误差量化。

## 1. “真实”分别证明了什么

Net1 / Net3 是来自 EPA/WNTR 的真实公开工程模型文件，保留上游字节与许可；结果由真实数值引擎计算。它们没有本项目的现场测量、参数校准或留出数据验证。来源正确、方程一致、数值收敛、与实测吻合是不同的证据，不能互相替代。

该模型在各水力时刻求解不可压缩水的网络平衡，并更新水箱储水量。适用目标是分钟至小时的压力、供水、漏失和启停方案比较。任意加密该模型的时间步，都不会自动增加管壁弹性、压力波传播或气液两相方程。

## 2. 现实因素逐项核对

下表中的“支持”指本仓库确实编译并计算；“未验证”不能展示成工程事实。

| 因素 | 已实际考虑 | 当前缺口及其影响 |
|---|---|---|
| 拓扑、高程、长度、直径 | 使用源 INP 的连接关系、物理尺寸和节点高程；压力为水头减高程 | 没有现场竣工核验；绘图坐标单位未知，不能当成 GIS 距离 |
| 沿程摩阻、局部损失、逆流 | Hazen–Williams 摩阻、源局部损失系数；拆管分配局部损失，保留逆流符号 | 新增粗糙度 C 倍数场景；未现场校准，未模拟结垢造成的直径演化。低雷诺数仅筛查，未实现层流/过渡区 Darcy–Weisbach |
| 用水时变、空间差异 | 源需求类别/时序、全网需求倍数；新增指定节点需求倍数 | 示例时序不能替代水表/SCADA。没有随机峰值、真实消防事件时序、用户行为或需求相关性数据 |
| 压力不足时供水减少 | 全局 Wagner PDD；新增 WNTR 各节点最低/满足压力，独立复算实际供水 | PDD 是聚合服务代理，未显式模拟楼层、服务管、室内泵和用户水箱。当前验证 WNTR 指数限定 0.5，未把不可靠的自定义指数当成支持 |
| 水源边界 | 源水头/源时序；新增水源基准水头偏移 | Reservoir 是外部定水头边界，不代表真实水厂产能、供电或处理能力限制 |
| 水箱状态与储水 | 源初始水位、容积/液位关系、液位上下限及源控制；故障前后连续更新 | 新增初始水位偏移、内部事件储水守恒；预热一小时不保证周期稳态。没有现场初始状态同化，也未分析溢流和空气过程 |
| 泵 | 源固定速度 H–Q 曲线、实际运行点、启停和源控制；新增扬程一致性、液压能和估算电能 | 没有变速调度、启停加速度、电机动态、磨损、NPSH 或气穴。效率来自源曲线/默认值，不能当作实测耗电 |
| 阀门、隔离、操作 | 普通管段的理想状态开闭、源止回行为、精确拓扑隔离边界 | 普通管段可操作目录是工程假设，不能证明该位置有真实阀门。没有本项目验证的 PRV/FCV/节流调度、阀门开度曲线、行程和执行器延迟 |
| 泄漏、背景漏损 | 固定面积的大气孔口；新增节点背景孔口，与用户供水分开计量 | 没有压力引起的裂缝面积变化、土壤阻力/饱和、外部水位与反压；Cd 和面积均为假设，需观测校准 |
| 断裂、修复 | 双端断口、故障期间断开、指定结束时刻恢复，水箱历史不断开 | 没有断裂结构力学、渐进破坏、抢修过程或充排气；修复时刻为外部输入，恢复为理想瞬时状态 |
| 快速瞬变 | 无 | 水锤、管壁弹性、流体压缩性、空气、液柱分离均未建模；不能用于秒级启停/关阀安全判断 |
| 负压、污染、水质 | 保存模型负压力和节点/时段，作为违反证据 | 负压不代表已求解气穴、侵入或污染输运。本模块明确关闭水质求解，未给余氯、水龄或污染结论 |
| 不确定性 | 实算需求、C、水源、初始水位、Cd、破口位置、维修延迟、局部需求/服务压力、背景漏损场景 | 单因素扰动和四种 A/B 场景不是联合概率分布、蒙特卡洛置信区间或现场可靠性保证；未覆盖所有同时变化组合 |

引擎功能边界以 [WNTR 1.5.0 官方框架说明](https://github.com/USEPA/WNTR/blob/1.5.0/documentation/framework.rst) 为依据；本项目支持集还受到编译器和已验收网络的限制，不能把引擎具备的全部功能直接计为已实现。

## 3. 算法判断和本次优化

EPANET 使用 Global Gradient Algorithm，WNTR 使用稀疏 Newton 方法求解水力平衡。本项目采用现有求解器，而非自行发明替代算法；当前系统规模没有改换遗传算法等方法求解水力方程的证据。[官方水力说明](https://usepa.github.io/WNTR/hydraulics.html)

这两个求解器解决给定操作下的压力/流量；决定怎样操作是另一个搜索问题。固定 A/B 脚本仅证明指定动作在指定场景中改善，不证明全局最优、Pareto 最优或 Agnes 已决策。完整优化还应冻结合法动作集合、目标、硬约束、评估预算，以枚举/图分析基线检查搜索结果，再研究多目标或稳健策略。

本次真实改动如下：

1. **显式物理参数进入 TaskSpec 和输入哈希。** 粗糙度、水源、水箱、局部需求/服务压力和背景漏损确实作用于引擎；未知节点、不合理水位、EPANET 不支持的局部 PDD/背景漏损均拒绝。
2. **内部计算与展示采样分开。** 0.4 WNTR 保存所有被接受的水力/控制事件；EPANET 按水力步长输出。900 s 公共 Series 保持兼容，新的 `hydraulic-analysis.json` 使用内部数据计算体积、最低压力和违规节点/最差时刻，避免用展示采样代替精细分析。
3. **独立方程检查扩展。** 在原连续性、孔口和泵曲线点检查上，加入管段能量方程、泵实际扬程、Wagner 供水定律、关闭流量、水箱液位及事件分辨的储水守恒。主动破坏水头/储水数据的测试确实被这些检查捕获。
4. **记录实际求解残差与迭代。** 记录 WNTR 每次 Newton 求解的最终无穷范数、迭代数和耗时。默认 0.4 残差容差为 1e-8；它是混合方程数值残差，不是“压力误差 1e-8 m”。
5. **更精细的 EPANET 求解选项。** 0.4 使用相对精度 1e-5、最大水头误差目标 0.001 m、流量变化目标 1e-7 m³/s、最多 200 次迭代。核实 WNTR 1.5 的 INP 写入实现后，将后两项转成原生 INP 单位，避免把 m³/s 数值直接当成 GPM；迭代警告仍判无效。[EPANET 算法及收敛标准](https://github.com/USEPA/EPANET2.2/blob/master/User_Manual/docs/12_analysis_algorithms.rst)

不能只看引擎“收敛”。独立门限见每次 `physical-checks.json`；EPANET 浮点输出和 PDD 数值近似采用明确的绝对+相对容差，不删除原始差值。WNTR 供水平滑过渡带单独计数；近零流量处不使用未经修正的 HW 方程去错误判定。EPANET 规则事件不一定出现在固定报告网格，水箱差分只作诊断，不冒充完整事件储水证明。

## 4. 实际实验结果

[26 组摘要](../benchmarks/physics/summary.json) 和 [完整证据](../benchmarks/physics/verified-results.zip) 包含实际引擎输入、CSV、物理检查、残差与哈希。相同时间线和参数下逐级加密 Net3 双端断裂；下表不是现场测量。

| 水力步长 | 缺供 m³ | 漏失 m³ | 最低压力 m | Newton 总迭代 |
|---|---:|---:|---:|---:|
| 300 s | 1649.3531 | 10757.9366 | −14.95653 | 118 |
| 150 s | 1650.3384 | 10754.1904 | −14.96393 | 187 |
| 75 s | 1650.8308 | 10752.3196 | −14.96762 | 329 |

150→75 s 的缺供变化约 0.0298%，漏失变化约 0.0174%，最低压力变化 0.00369 m。该案例达到程序明确声明的“相邻细化结果体积变化 ≤0.1%、压力变化 ≤0.02 m”数值比较目标。它不是对现场真值的误差上界，也不能自动证明其他任务 75 s 足够。控制切换或参数变化应重新做细化。

同样 300 s 下，将 Newton 容差由 1e-6 收紧至 1e-8，缺供差仅约 2.65e-8 m³，迭代从 107 增至 118。可见继续收紧代数容差对该工程指标收益很小；水力时间离散和物理输入的不确定性更值得处理。没有用一次进程耗时声称算法提速。

单因素场景均与 300 s 原案例比较：

| 场景 | 缺供 m³ | 相比基准 |
|---|---:|---:|
| 原断裂 | 1649.353 | — |
| 总需求 +10% | 1860.253 | +210.899 |
| HW 粗糙度系数 C −20% | 1729.890 | +80.537 |
| 水源水头 −2 m | 1657.538 | +8.185 |
| 初始水箱水位 −0.3 m | 1653.853 | +4.500 |
| 修复延迟 15 min | 2015.555 | +366.202 |

其余 Cd、破口位置、局部需求/PDD、背景漏损案例全部保留在摘要中。C 降低会同时影响供水和漏失，不能仅看“漏失变小”就判断更好。这些结果只表明本案例敏感性，不代表通用参数重要性排序。

共同支持的 Net3 关闭工况在 75 s 下，WNTR/EPANET 缺供差约 0.00344 m³，最低压力差约 1.57e-6 m。两个实现一致增强了数值可信性，但没有消除共享的物理假设。

同条件 A/B 在 150 s 内部采样下：

| 场景 | A 缺供 m³ | B 缺供 m³ | B 最低压力 m |
|---|---:|---:|---:|
| 名义 | 192.076 | 7.928 | 2.635 |
| 需求 +10% | 368.944 | 23.327 | 2.163 |
| C −20% | 522.522 | 44.845 | 2.106 |
| 水源 −2 m | 194.462 | 8.821 | 2.593 |

B 在这四个场景均改善缺供，同时增加泵能耗，且最低压力仍未达到 20 m。旧 0.3 的 900 s 参考指标是 A 187.306、B 7.702 m³；差异来自时间采样，不能在前端混用。四种固定场景未满足任务全部扰动准入和证据要求，不把它们自动写成推荐通过。

## 5. 接入与复现

从仓库根目录运行（Linux 用 `.venv/bin/python`）：

```powershell
.venv/Scripts/python.exe -m services.hydraulics.cli example --network epa-net3 --kind rupture --physics --output artifacts/request-v4
.venv/Scripts/python.exe -m services.hydraulics.cli simulate --task artifacts/request-v4/task.json --plan artifacts/request-v4/plan.json --output artifacts/jobs
.venv/Scripts/python.exe -m services.hydraulics.physics_study --output artifacts/physics-study --summary artifacts/physics-summary.json --export artifacts/physics-study.zip
.venv/Scripts/python.exe -m services.hydraulics.server --output artifacts/physics-study
```

`physical_case()` 生成 0.4 TaskSpec/ActionPlan；每次改变参数后使用 `rebind()` 更新哈希，同条件候选共享同一 TaskSpec。`node_pdd` 与背景漏损目前限 WNTR；EPANET 使用全局 PDD。粗糙度倍数是 C 的倍数，不是管壁绝对粗糙度 mm。`solver_tolerance` 仅控制 WNTR；EPANET 固定采用本版上述精度准则，不能将该字段解释为 EPANET 误差目标。

同学 2 通过 `/api/simulations/{id}/analysis` 或证据文件取得内部时间分辨的量化结果和节点最差时刻。正式验证器需要使用内部数据复算指标并逐时刻检查硬约束；仅按公共 900 s Series 得到的 `VerificationReport` 是粗网格参考报告。`dense_constraint_diagnostics` 是阈值测量与位置诊断，不替代正式五层准入。

同学 3 同时展示原始压力、内部最差时刻、展示步长/计算步长和模型适用尺度；不要把负压改成零，也不要把电能估算展示成电表读数。

## 6. 进入实际工程使用的优先级

首先要让具体网络模型吻合实测：核对竣工拓扑和阀门位置，接入需求、压力、流量、源水头、水箱液位、泵 H–Q/效率和实际操作记录；用一组数据标定，再用独立时段和故障验证，保留残差与参数辨识的不确定性。当前场景实验已说明需求/C/维修时长值得优先核实。

若研究目标包含快速启停/关阀，必须另建瞬变模型并与延时模型耦合。需要管材、壁厚、弹性/波速、支撑约束、阀门行程、泵转动惯量及气穴/空气边界数据；没有这些输入，增加一个默认“水锤修正系数”不会形成真实实现。

若现场破口处于受压土壤/积水环境，需引入经实验验证的面积–压力/外部反压关系，再做基准对比；若目标包含污染风险，需补充相应输运与反应模型。分别按问题和现场数据增加物理模型，而不是把未验证参数塞进一个“全因素”标签。

当前优化已经可执行、可重跑；上述缺项明确保留，不能将“公开模型上真实运行”扩大成“现实物理因素全部覆盖”。
