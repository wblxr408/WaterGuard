# WaterGuard Agent 设计

版本：0.3；日期：2026-10-05；状态：官方 AGH 源码与原生工具已接入，模型驱动的任务仍待有效凭据验证。

规则澄清：用户重新核对的要求是核心任务的组织、执行或工具调用必须使用 AGH；模型可使用赛事 Agnes，也可接入允许的开源或第三方模型。WaterGuard 默认选择赛事 Agnes，同时支持 DeepSeek 和 GLM。成果展示使用 WaterGuard 自有界面，通过 SDK 接入 AGH，无需从官方 Web 发起任务。下文的“Agnes”表示当前默认模型的角色，不表示赛事只允许该模型。

本文定义核心任务由谁组织和执行、三个 Agent 如何分工、工具调用如何治理，以及如何证明 Agnes 与 AGH 实际参与。配套文档：[后端设计](后端设计.md)、[前端设计](前端设计.md)。当前版本优先于旧 HTML 蓝图中的架构说明。

## 1 规则复核与计划修改

按用户最新提供的规则，所有作品必须使用 AGH 完成核心任务的组织、执行或工具调用；Agnes 自研模型可选，其他合法可用的模型也可接入。设计文档或模拟界面不能当作真实执行成果。

旧计划有治理层、仿真和多角色分工，方向可以保留。必须消除“后端控制器组织全部业务，AGH 只是一个调用适配层”的歧义：

| 原设计中的不明确之处 | 本版决定 | 验收依据 |
|---|---|---|
| 后端和 AGH 都像核心编排者 | 核心规划、工具选择、反馈修正和审查协调在 AGH 会话中执行 | 原生 AGH 记录可追到工具调用及反馈 |
| Agnes 可能仅做解释或总结 | Agnes 选择策略，并根据验证结果决定下一步 | 至少一个真实失败反馈触发方案修正的案例 |
| 仿真链可能藏在全自动工具里 | 拆成检查、候选、仿真、验证、复验等可观察工具 | AGH 读取中间结果并影响下一步 |
| 自建日志可能被当作 AGH 证据 | 保存 AGH 原始导出及关联索引，应用日志作为补充 | 两类记录能关联到同一调用 |
| 多 Agent 原生能力未核验 | 核验后采用原生委派；否则在同一 AGH 会话分阶段执行 | 如实标记实际模式 |

~~~mermaid
flowchart TD
    U["用户工作台"] --> A["API：启动或恢复 AGH"]
    A --> H["AGH 会话：Agnes 规划与核心执行"]
    H --> T["任务建模角色"]
    T --> P["方案规划角色"]
    P --> G["WaterGuard 工具网关"]
    G --> C["确定性图分析与候选生成"]
    G --> S["水力仿真进程"]
    G --> V["程序验证与证据库"]
    C --> H
    S --> H
    V --> H
    H --> R["反例审查角色"]
    R --> G
    H --> F["有证据引用的结论"]
    F --> U
    B["后端治理：授权、预算、取消、版本"] -.约束.-> G
    B -.生命周期管理.-> H
~~~

后端可以排队和取消作业、执行数值算法、强制检查约束，不能另起一个智能循环替代 AGH。AGH 工作流模板可以规定阶段，但具体候选选择、工具参数和反馈修正须体现 Agnes 的实际作用。

## 2 产品任务与运行边界

输入是已知故障位置、网络模型、时间窗口、允许设施操作和保供要求。输出是候选方案、对照结果、违反项、复验覆盖及可复现证据。

首版聚焦单一管段故障。多个故障作为扩展或边界案例；修理队路线、未知漏点定位、水质推断和水锤分析不计入首版承诺。三维场景不扩展物理模型能够证明的范围。

任务区分目标、硬约束、软偏好、允许动作、扰动域和假设。每个阈值有来源，每个动作有设施、参数范围、时段和前置条件。“优先保障医院”不直接等同于任意压力阈值。已有模板可使用有来源的预设；关键条件缺失时返回结构化澄清请求。更改硬约束产生新任务版本。

## 3 AGH 接入核验

公开 Agnes Code 文档介绍 MCP、子代理和权限，但不能单独证明赛事 AGH 发行版具有相同接口。本文工具名、JSON 和内部适配接口都是项目设计，不是官方 SDK 声明。

正式功能开发前完成以下探针，并保存实际版本、配置和输出：

1. 核验赛事指定 AGH 安装方式、版本及 Agnes 模型标识、认证与一次模型调用。
2. 通过 AGH 调用最小网络检查工具，再接入小型真实水力仿真。
3. 在核心会话中连续完成检查、调用、反馈处理与验证，确保反馈重新进入 Agnes 上下文。
4. 验证原生子代理、上下文隔离及可信角色身份如何绑定工具权限。
5. 验证日志导出、工具标识、恢复与取消。缺原生调用标识时建立可核对的宿主映射，不伪造原生字段。
6. 核查实际模型、提供商、工具与扩展配置，覆盖后台总结、审查和标题生成等模型调用。

优先使用该发行版支持的 MCP 或官方工具扩展。原生子代理不可用时，降级为单 AGH 会话的三个角色阶段，并如实标记；如果核心工具闭环或真实执行证据无法实现，记录接入阻塞，不用其他框架或模型冒充完成。

## 4 三个角色

| 角色 | 输入 | 可作出的决定 | 输出 | 权限边界 |
|---|---|---|---|---|
| 任务建模 | 用户需求、网络目录、来源 | 解释字段、标出歧义、提出草案 | TaskProposal | 不修改已冻结条件，不隐去未知项 |
| 方案规划 | TaskSpec、动作目录、工具结果 | 选择生成策略、动作组合及修正方向 | ActionPlan、DecisionRecord | 不降阈值，不写入验证通过 |
| 反例审查 | 候选、验证及数据引用、已测场景 | 指出缺失证据，选择域内扰动复验 | StressTestRequest、ReviewFinding | 不改原候选、任务或授权范围 |

任务建模通常在开始或修订时调用一次；规划贯穿搜索与修正；审查在有希望的名义候选出现后介入，避免对明显无效候选反复耗费预算。

共享不可变任务与产物引用；角色上下文按需取数。审查者获得原始约束和结果，避免只读取规划者的自我评价。决策记录保存简短理由和依据，不收集隐藏思维链。同一模型的角色可能产生相关错误；角色一致不替代程序验证。

## 5 核心执行流程

1. API 建立运行记录并启动 AGH，后台负责生命周期与治理。
2. 任务建模角色调用 wg_inspect_network，然后 wg_propose_task。
3. 网关检查草案。输入完整且在用户授权内时冻结 TaskSpec；实质歧义进入 NEEDS_INPUT，用户答复后经宿主恢复 AGH。
4. 规划角色通过 wg_submit_plan 提交故障基线的空动作方案，调用 wg_simulate_candidate、wg_verify_candidate。
5. Agnes 选择 wg_generate_candidates 的策略或直接提出 ActionPlan；生成工具返回候选。
6. AGH 调用仿真和验证；工具返回指标、失败类型、最差节点/时段及产物引用。
7. Agnes 根据反馈修改动作或策略，再经 AGH 发起下一轮；记录父候选和变更原因。
8. 审查角色调用 wg_create_perturbation，再仿真和验证；规划者根据结果决定是否修正。
9. Agnes 选择候选，调用 wg_build_evidence。后端校验准入条件，Agnes 引用证据形成结论。
10. 记录终止原因和结论范围，区分可行、未找到、预算结束、错误和取消。

禁止一个 solve_everything 工具包办任务解释、尝试、审查及报告，AGH 只调用一次后复述结果。确定性图算法、有限候选生成和数值求解允许作为工具内部计算。已经满足目标时可以提前结束，不为展示多轮而制造失败。

## 6 工具契约与角色权限

自定义工具采用 wg_ 前缀；实际挂载协议在接入后锁定。

| 工具 | 主要参数 | 结果 | 角色 |
|---|---|---|---|
| wg_inspect_network | network_ref | 摘要、动作目录、来源 | 全部 |
| wg_propose_task | task_id、proposal | 冻结快照或澄清字段 | 任务建模 |
| wg_generate_candidates | task_ref、strategy、candidate_limit | 候选引用、生成诊断 | 规划 |
| wg_submit_plan | task_ref、actions、parent_candidate_id? | 候选或非法动作错误 | 规划 |
| wg_simulate_candidate | task_ref、candidate_id、perturbation_id? | 产物引用或作业句柄 | 规划；审查仅复验已有候选 |
| wg_get_simulation | simulation_id | 状态与结果引用 | 规划、审查 |
| wg_verify_candidate | simulation_id | VerificationReport | 规划、审查 |
| wg_create_perturbation | task_ref、candidate_id、parameters | 扰动场景或越界错误 | 审查 |
| wg_compare_candidates | task_ref、candidate_ids | 同口径指标与 Pareto 候选 | 规划、审查 |
| wg_build_evidence | run_id、selected_candidate_id? | 证据包及准入结果 | 规划 |

真实角色和会话身份由宿主与服务端凭证绑定，不信任模型自报 role 或 session_id。如果没有可信子代理身份，采用独立受限端点/进程；仍不能隔离时采用分阶段单会话，不声称已实现角色隔离。

统一返回 status、code、data_ref、summary、violations、retryable、remaining_budget、correlation_id。大数组保存在产物中，摘要能定位到节点与时段。数据文件和工具输出里的文本不能成为新系统指令。

## 7 边界治理

| 边界 | 强制机制 | 反馈 |
|---|---|---|
| 硬约束 | TaskSpec 只读、constraint_hash 校验 | TASK_REVISION_MISMATCH |
| 动作 | 设施目录、参数、时序和物理映射 | INVALID_ACTION |
| 角色 | 服务端能力矩阵 | PERMISSION_DENIED |
| 结果 | 原始产物复算、版本及完整性检查 | ARTIFACT_INVALID 或具体违反项 |
| 资源 | 派工前原子预留模型/仿真预算 | BUDGET_EXHAUSTED |
| 数据 | 结构化解析，内容不改变指令权限 | INPUT_INVALID |
| 模型 | 冻结本次运行选定的账号路由、模型与提供商；支持 Agnes、DeepSeek、GLM | MODEL_NOT_ALLOWED |
| 结论 | 推荐准入与覆盖范围分离 | ELIGIBILITY_INCOMPLETE |

目标边界是不向核心 Agent 开放任意 shell、运行时生成代码执行、任意网络请求、直接数据库写入或替换验证器。业务工具自身不调用其他模型，不启用隐式 MCP sampling；总结与审查等辅助调用也纳入本次 AGH 模型配置。实际工具权限以已核验的 AGH 配置为准。

例如模型提议把最低压力从 20 m 降到 14 m，网关应拒绝。继续寻找合法方案，或生成独立的任务修订建议供用户决定。原运行不能因此变成通过；数值为治理示例，不是统一工程标准。

## 8 失败与恢复

起始预算建议最多 4 轮修正、40 次仿真（含基线、失败尝试和扰动）、2 个并发计算进程。模型预算和超时实测后确定，这些数字不是性能承诺。审查共享总预算，并事先预留额度。

- 模型格式错误最多修复一次，仍失败则停止该阶段。
- 工具临时错误按声明重试；请求幂等，实际尝试计入资源消耗。
- 仿真不收敛属于计算无效，不计通过，也不证明无解。
- 预算结束返回最佳已验证候选和未完成项；没有候选则说明未找到。
- 审查失败保留名义验证，不标记复验完成。
- 取消同时传递给 AGH 与计算进程；迟到结果归档，不能覆盖取消状态。
- 恢复优先续接真实 AGH 会话；不支持时建立关联新会话并记录边界，不伪装连续执行。

## 9 证据与参赛交付

每次正式运行保留 AGH 原生记录、版本、Agnes 模型信息、角色/阶段、工具标识或核验映射、参数、返回结果、TaskSpec、网络哈希、候选和扰动、原始时序、验证及修正依据。

应用标准化事件不是 AGH 原始日志。历史回放必须来自真实运行并标注；禁止事后补造调用、失败或数值。日志脱敏不改写工程结论，证据包不含密钥，脱敏范围和文件哈希可核查。

| 截图要求 | 项目交付安排 |
|---|---|
| 可运行作品 | 真实 AGH 工具闭环与复现入口；HTML 仅为设计资料 |
| AGH 与 Agnes 核心参与 | 原生会话、决策变化、调用和反馈证据 |
| 专业工具或仿真 | 水力产物、验证、动作映射 |
| 执行记录、测试和专业验证 | 正常、边界、失败案例及指标复算 |
| 学生独立完成与真实成果 | 记录成员贡献、开发工具使用和成果来源 |
| 第三方资料披露 | 数据、代码、图片、3D 资产来源与许可清单 |

开发阶段其他 AI 工具的边界不能由运行时规则推断；提交声明以主办方最新说明及实际使用为准。

## 10 对照评测

设置固定规则、固定搜索、单 Agent、多 Agent 四组。前两组是标记为 benchmark 的实验对照，不能冒充正式 AGH 核心流程；正式运行通过 AGH。

固定网络、动作域、仿真参数和总仿真次数；单/多 Agent 还需统一模型总预算与墙钟上限。重复运行，记录种子、模型参数与实际消耗。报告完成率、合法动作率、硬约束满足率、未检出违规、用户缺供量、耗时和调用成本。

开发与留出场景按网络/故障/需求组合分组，同一案例的小扰动不能分散后声称泛化。初始建议 30 个开发场景与至少 10 个留出场景，随计算预算调整；尚未取得实验结果。

多 Agent 保留依据是同等资源下净收益。若只增加耗时而无可靠改善，作为可选模式保留，不用角色数量代表创新有效。

## 11 里程碑与验收

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| AGH 探针 | 配置、工具、连续步骤和原始日志 | 核心调用来自 AGH，反馈回到 Agnes |
