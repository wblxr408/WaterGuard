# 同学 1：仿真与数据交付

本模块将冻结的 TaskSpec 和 ActionPlan 编译成真实 WNTR/EPANET 计算，交付原始时序、物理检查和可回放证据。使用 EPA Net1（调试）、Net3（展示）公开示例，来源、许可、原文件 SHA-256、单位与坐标说明见 [数据说明](../data/README.md)。这些模型没有现场校准；故障参数是明确记录的试验假设。

当前实现版本为 contracts **0.3.0**，保留 0.1 Fixture 和 0.2 EPANET Adapter 的兼容入口。主要入口是 [PhysicalAdapter](../services/hydraulics/runtime.py)，同学 2 可直接接入。

## 安装与完整重跑

从仓库根目录执行，Python 3.11；Linux/macOS 用 `.venv/bin/python`：


验收矩阵有 22 个真实计算：每个网络 WNTR 正常、关闭、泄漏、断裂、隔离、泵循环、管段循环 7 个；EPANET 正常、关闭、泵循环、管段循环 4 个。A/B 反馈样例再计算 2 个候选。所有调用分配新的目录和进程，失败也保留诊断。

已计算的交付证据位于 [benchmarks/student1](../benchmarks/student1/)，无需先安装引擎即可查看摘要或解压 CSV。安装后可离线重算，上游重新下载仅在显式 `datasets --fetch` 时发生。

## 故障和动作的物理定义

| 类型 | 实际编译行为 | 支持引擎 |
|---|---|---|
| `closure` | 在指定时刻关闭既有管段，到结束时恢复其初始状态；没有泄漏 | WNTR / EPANET |
| `leak` | 按 `location_fraction` 拆管，加入指定面积与流量系数的单个大气孔口，`Q=Cd·A·√(2gh)` | WNTR |
| `rupture` | 拆成两个断口，每端按原管截面积向大气出流；断口之间无流通 | WNTR |
| `isolation` | 关闭任务指定的精确拓扑边界，验证被围区域无水源/水箱；区域内期望需求仍计入缺供 | WNTR；当前已验收 WNTR |
| `link_open/close` | 对操作目录中的普通管段施加定时状态控制 | WNTR / EPANET |
| `pump_on/off` | 对目录中的固定速度 HEAD 泵施加启停控制 | WNTR / EPANET |

断裂模型在故障前后使用长度 `1e-6 m` 的虚拟连接维持连续预热和修复过程，故障期间关闭该连接并打开两个断口。保存映射与连接流量，测试故障期连接流量为零；故障前压力对正常模型允许误差 0.002 m、水箱体积 0.02 m³。拆管按比例分配原局部损失，避免重复计算。该模型是延时水力模拟，不计算水锤或真实破口演化。

原有自动控制默认保留。若故障或动作触及有源控制的设施，必须在 `control_policy.overrides` 中写明完整、排序一致的控制名和原因。覆盖对整个任务时间线生效，所以比较候选必须使用同一冻结 TaskSpec；不得只给 B 删除自动控制。

## 同学 2 的接入接口

```python
from services.hydraulics.runtime import PhysicalAdapter
from services.hydraulics.scenarios import case

task, plan = case('epa-net3', 'leak', 'wntr')
adapter = PhysicalAdapter('artifacts/jobs')
result = adapter.simulate(task, plan, timeout_s=60, cancel_event=None)
if result['artifact']['status'] == 'SUCCEEDED':
    page = adapter.get_series(result['artifact']['simulation_id'],
                              node_id='123', start_s=3600, end_s=7200)
```

`cancel_event` 接受具有 `is_set()` 的 Event（例如 `threading.Event`）。Adapter 同步等待，后端应在后台作业中调用；设置 Event 后停止并回收计算进程，返回 `CANCELLED`。`timeout_s` 与任务预算取较小者；超时返回 `FAILED/TOOL_TIMEOUT`。无效 JSON、Schema 或输入哈希在启动前拒绝；进入 worker 后的物理编译错误返回 `FAILED/INPUT_INVALID` 并留证。调度并发槽、总调用预算、权限、任务修订及 SSE 仍由作业系统负责。

也可通过 JSON 文件运行，无需在服务进程里引用 WNTR：

```powershell
.venv/Scripts/python.exe -m services.hydraulics.cli example --network epa-net3 --kind leak --output artifacts/request
.venv/Scripts/python.exe -m services.hydraulics.cli simulate --task artifacts/request/task.json --plan artifacts/request/plan.json --output artifacts/jobs --timeout 60
```

成功输出完整 SimulationResult，退出码 0；失败结果退出码 1。修改任务/方案后需通过权威 Python `task_hash/plan_hash/task_ref` 重算绑定，不能只修改 JSON 字段。

任务显式指定 PDD 最小/满足压力、指数、水力步长、需求倍数。当前支持从 t=0 开始、最长 7 天、报告步长至少 60 秒且整除时段、水力步长整除报告步长；故障与动作对齐报告时刻。首小时是共同预运行，不宣称稳态。默认 300 秒水力步长、900 秒输出步长。

## 时序与证据的含义

- `nodes` 只包含原模型 junction：期望需求、实际用户供水、压力。新增孔口放在 `leaks`，不进入用户供水分母。
- `links.flow_m3s` 是原起点的流入，`downstream_flow_m3s` 是原终点的流出；符号沿源管段方向。泄漏管两端流量可不同。断裂显示 `status=broken`、`physical_state=ruptured`。
- `tanks` 给出水头、水位、体积与净流入；内部拆管节点、边和源 ID 的对应见 `entity-map.json`。
- `series.frames` 表示 `[0,end_s)` 的间隔起点保持值。末时刻数据保留在原始 CSV 中；缺供和泄漏体积是报告步长近似积分。
- 原始 CSV 保留引擎值。仅输出层将 `[-1e-9,0)` m³/s 需求误差置零并记录警告；更大负需求、缺失帧、非有限值、未知警告、物理检查失败均使结果无效。

`physical-checks.json` 检查所有编译 junction 的质量守恒（`2e-6 m³/s`）、活动孔口公式（相对误差 `1e-4`）、非活动孔口零出流、源泵曲线点拟合（`1e-4 m`）。Net3 三点泵曲线的三参数拟合会出现“无法估计协方差”警告；仅该精确已核查警告允许保留，仍必须通过点值检查。其他引擎警告拒绝成功。

每个运行目录含输入/许可、任务与方案、source/overlay 哈希、编译模型 JSON、entity map、原始 CSV、结果、诊断、环境、进程执行信息和文件清单。EPANET 运行另含实际 INP/RPT/BIN。WNTR 的泄漏扩展以 `compiled-network.json` 保存，不能用不支持该映射的 INP 代替。引擎标识绑定适配器/公共校验代码 SHA-256。

检查已有证据并重新计算：

```powershell
.venv/Scripts/python.exe -m services.hydraulics.replay artifacts/student1/sim-替换为实际ID
```

## 真实 A/B 反馈样例

Net3 管段 123 在 `[3600,7200)` 秒关闭，同一任务显式将 Lake 泵 10 转入手动控制，初始仍关闭。A 不动作，B 在 3600 秒启动泵 10。两者的预热、网络、阈值、故障和控制策略相同。

实际计算得到 A 缺供约 **187.306 m³**，B 缺供约 **7.702 m³**；最低压力由约 **−24.473 m** 改善到 **2.634 m**。B 仍未达到 20 m 压力约束，准入状态保留失败。负压力是该延时/PDD 模型的输出和违反证据，不表示现场负压工况已获验证。不能为演示成功裁剪负压力或降低阈值。

这组工程样例由固定脚本产生，可供后端验证工具接入与反馈展示。后续 Live 链路仍须 Agnes 真正读取 A 的验证结果并选择下一动作，附 AGH 原生日志，才能证明 Agent 闭环。
