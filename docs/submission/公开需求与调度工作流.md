# 公开需求与调度工作流

本需求说明采用公开应急预案与项目可核查行为，没有水司访谈、合作部署或现场运行记录。

[北京市供水突发事件应急预案（2024年修订）](https://yjglj.beijing.gov.cn/art/2024/12/9/art_2522_683696.html)于2024年12月9日发布。其1.3描述设备故障、管网破损和水源不足等风险；1.4强调减轻停水影响；2.3明确水源调度、设施和管网事件调查职责；4.5包含事故排查、抢修与视情启用备用设备。2026-10-12直接读取原文核对。

由这些职责推导，WaterGuard面向的操作流程为：调度员输入已知故障、可操作设施和评价窗口，冻结工程阈值与响应延迟；AGH依据真实仿真反馈搜索方案；独立验证器给出每个节点的正常与降级服务时长；调度员对照无动作基线、检查剩余低压和缺供、查看原始报告后决定后续处置。这是需求分析推导，不声称已验证真实调度员使用效果。

| 工作环节 | 作品中的可核查支持 | 人工复核点 |
|---|---|---|
| 判断故障与操作条件 | 故障位置、时间、类型及冻结设施域 | 实际事故信息、阀泵状态与操作授权 |
| 比较应急动作 | 同窗无动作基线、多设施隔离和备用泵候选 | 设备能力、实际检测与执行延迟 |
| 尽量挽救供水 | 全程达标节点数、逐节点平均/最差时长、降级覆盖与基线改善 | 剩余缺口是否需要送水、抢修或进一步措施 |
| 判断可推荐性 | 名义硬约束、同计划需求增长复验和原生证据分别准入 | 存在失败项的方案不能当作完全达标 |
| 交接与复核 | 原生工具事件、原始水力区间、任务/计划与独立报告 | 数据来源、模型假设和证据缺失 |

20m/95%与15m/75%为本项目明确冻结的工程假设，后者由用户确认作为附加应急层；不将其说成该公开预案规定的法定阈值。平均时长占比按节点等权，不等于人口比例或用水量覆盖。公开模型没有真实医院或居民人口标签，当前不会虚构民生优先级。

错误决策的具体风险是把全网总供需比掩盖的局部低压当作恢复，或忽略动作前延迟期的失供。作品因此保留全部评价秒数、最差节点与剩余供水缺口，并把部分改善作为明确的尽力挽救交付。现场应用还需管网校准、实时数据、设备能力及人员处置流程验证；本次交付是可复现的仿真决策作品。
