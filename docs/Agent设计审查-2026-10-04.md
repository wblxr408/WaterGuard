## 3 已复现的问题

本次在临时目录和开发工具调用中复现，无真实 AGH 会话、无硬件操作。结果保存于本机忽略的 `artifacts/agent-audit-20261004/reproductions.json`。

1. 在同一 task/revision 改低压力阈值，重新计算 task/plan 哈希后，`wg_submit_plan` 返回 `CANDIDATE_ACCEPTED`。这证明内容自洽校验不能替代服务端任务冻结。
2. `physical_case('epa-net1','leak')` 的 0.4 任务提交到 `wg_propose_task`，返回 `INPUT_INVALID: Unapproved action catalog reference`。
3. `candidate_limit=1` 返回 2 个候选。初始 baseline 已占一个名额，枚举进入循环后才检查上限。
4. 对现有名义验证报告调用比较工具，返回空 `eligible_candidate_ids`、`selected_candidate_id=null`。当前报告始终保留 benchmark/fixture 和复验未完成阻塞，不能用最终准入替代搜索比较。
5. 将开发 run 的调用参数标为 live，在 native 目录下只建空子目录、association 写 `{}`，`agh_session_ref=null`，仍得到 `live_export_allowed=true`、`missing_items=[]`。这里只是对函数入口的反例，不是真实 live 证据。

## 4 设计本身的优化

以下是进一步优化建议，尚未完成效果验证。其中涉及正式来源、错误处理和数据契约的部分应随核心缺口一起实施；多 Agent 与搜索效果优化可放到首个真实闭环之后。

| 编号 | 优化方向 | 建议实现 | 预期收益与验收方式 |
|---|---|---|---|
| O01 | 收敛首版角色组织 | 先交付一个 AGH 会话内的任务建模、规划、审查三个阶段；审查读取冻结约束与原始报告引用。原生子代理身份、权限和收益验证后再启用 | 降低首次接入复杂度；逐阶段记录输入输出与授权边界，没有可信隔离时如实标记 |
| O02 | 角色指令与决策记录 | 版本化角色指令；为 DecisionRecord/ReviewFinding 补完整 Schema，保存输入、反馈、父候选、动作、理由摘要、下一步和停止原因 | 失败后能定位修正依据；每个决策引用可解析，模型不能写入程序 pass 标记 |
| O03 | 异常分流与有限重试 | 临时错误按声明重试；约束违反交给 Agnes 改候选；身份、版本和预算错误终止请求；轮询设置间隔与截止时间 | 避免重复非法请求或高频轮询；相同非法动作不会无限自动重发，超时能结束并保留诊断 |
| O04 | 候选覆盖与组合动作 | 明确当前只枚举 0/1 动作；给截断结果返回覆盖诊断；设计有明确支持集合的 strategy，允许 Agnes 提交合法组合方案 | 减少按设施字典顺序截断的偏向；记录已覆盖设施、时段、动作类型及未搜索域，不声称全局最优 |
| O05 | 评测规模与公平对照 | 先做正常、失败修正、扰动失败、取消和恢复案例；再固定场景、模型预算、仿真次数、缓存策略开展搜索/单角色/多角色消融 | 先证明能运行，再衡量角色带来的收益；已有 50 次物理计算只作数值证据，不计入 Agent 决策实验 |
| O06 | 区分计算来源和运行来源 | 保留既有 benchmark 数值记录；真实 AGH 调用后新增 session、原生调用、应用事件与计算产物关联 | 结果来源可追溯；正式运行不靠把历史产物改名为 live 来证明，缓存命中明确标记 |
| O07 | 统一引用与工具反馈 | 为任务、候选、扰动、仿真和报告提供服务端引用及按需读取；统一错误码、剩余预算、correlation_id，并控制摘要大小 | 减少重复传完整 JSON 和上下文消耗；大时序留在产物中，摘要能定位节点/时段并读回依据 |
