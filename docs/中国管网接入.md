# 中国 Zhi Jiang 管网接入

工作台默认数据源和新建任务默认管网均为 **中国 Zhi Jiang（China 1）**，ID 为 `china-zhijiang`。界面拓扑来自原始 EPANET 模型，压力、流量、缺供和故障状态来自实际 WNTR / EPANET 仿真。

## 来源与范围

- 原始发布：[Dandy, Graeme, “06 Zhi Jiang” (2016), University of Kentucky Libraries](https://uknowledge.uky.edu/wdst_international/6/)。基于实际中国供水系统的历史设计优化研究模型，引用 Zheng、Simpson、Zecchin (2011)，DOI `10.1029/2011WR010394`。
- 下载使用发布者资料中有对应引用的 [WaterBenchmarkHub 镜像](https://github.com/WaterFutures/WaterBenchmarkHub)，固定提交 `3a3e7921b2672de46ea5dee4ae3c0ee84695ccad`。UKnowledge 的下载端点本次返回 403，未声称已与该端点的文件字节比对。
- 原始模型：`data/networks/zhijiang/ZhiJiang.inp`，38,546 字节，SHA-256 `54da00cfe97832f7d94f1cbbe1697d56f95c21053c7fde9cc8afdcac9ecb6563`。保留原始换行和内容。
- 数据许可：**CC BY-NC 4.0**，归属 Graeme Dandy / University of Kentucky Libraries。镜像软件的 MIT 许可不替代数据许可。每次仿真保留模型归属说明及独立 WNTR 求解器许可。
- 实际解析得到 113 个用水节点、1 个水源、164 条管道，总管长 126,436 m，无泵或水箱。源单位 LPS；原始需求总和约 5.55703 m³/s，按 INP 计算约 480,127 m³/day。发布页的约 484,000 m³/day 为叙述数值，本项目不调整需求去凑该数值。
- 保留来源名称 **Zhi Jiang**。尚未确认它对应的准确中文地名、真实地理坐标系或管道埋深，不将示意坐标冒充城市地图。

## 工况与显示

`services.hydraulics.china_demo` 生成七个工况：WNTR 的正常、关闭、泄漏、断裂、隔离，以及 EPANET 的正常、关闭。默认显示 WNTR 的正常与关闭对照，也可选择其他工况。故障目标为源模型的管段 `1`；隔离边界由该管段两端的实际连接关系生成并检查。

三小时观察窗口、故障发生在 1–2 小时、PDD 所需压力 20 m，以及泄漏/断裂参数均为明确的研究场景假设。PDD 参数控制压力与供水量的物理计算，独立于验收阈值。原始管径、需求、长度、高程保留。每次计算通过独立物理复核，并保存原始 CSV、源 INP、输入哈希、来源和许可。

## 自适应与手动阈值

2026-10-06 起，中国场景库与新建任务默认采用自适应验收：先在相同模型、PDD 和时窗下运行无故障、无人工动作的基线，对评估窗口的所有用水节点和原始报告时刻取最低压力、最低节点供需比，再分别乘以 95%。压力向下取至 0.01 m、供需比向下取至 0.0001。该模型 WNTR 的建议值为 **12.87 m / 78.19%**，原始基线最低压力约 13.55 m、最低节点供需比约 82.31%。这是一套允许相对基线退化 5% 的研究判据，供水缺口和原始计算数值仍按实际结果显示。

两项阈值、算法、基线仿真 ID、输入哈希及来源在任务创建时写入 `hard_constraints.source` 并纳入任务哈希；同一任务的故障及候选方案使用同一套冻结阈值。不得依据故障结果重新降低阈值。基线数值无效、存在非正压力或接近零的供水时，自适应不可用，界面要求选择手动模式。原有固定阈值的 EPA 工程验收用例继续保持原条件。

工作台顶部“调整阈值”可选择自适应或手动设置压力/供需比。应用后创建新任务、进行真实计算与独立验收，并将新运行的图、图例、曲线与违规列表一起加载到工作台；历史任务与结果保留原阈值。智能体页的新建任务使用同一功能。手动输入不改变 PDD、管径或需求参数。

基线证据保存在 `artifacts/threshold-baselines/`。缓存复用前校验源模型、overlay、任务哈希、引擎身份、原始输出及完整文件清单；引擎或输入变化后重新计算。导出的中国证据包同时包含 `threshold-references/` 和 `threshold-references.json`，用于复核自动阈值的依据。

`benchmarks/china-zhijiang/verified-results.zip` 保存此次实际计算证据，其 SHA-256 清单与压缩包一并保留。启动时 `--ensure` 根据源文件、overlay、当前引擎代码及完整证据检查缓存，必要时重新计算。

## 复现

在仓库根目录、依赖安装完成后运行：

```powershell
.venv/Scripts/python.exe -m services.hydraulics.datasets
.venv/Scripts/python.exe -m services.hydraulics.china_demo --ensure
.venv/Scripts/python.exe -m services.hydraulics.server --output artifacts/china-zhijiang --port 8003
```

完整工作台仍使用 `npm run start:web`，启动脚本自动准备中国管网产物并启动 8003 服务。前端通过 `/cn` 代理读取该数据源；EPA 原有数据源继续使用 8001/8002。新建任务界面默认选择中国模型，任务 API 接受 `network_id: "china-zhijiang"`，可执行用户选择的关闭、泄漏、断裂、隔离或正常场景。

## 验证

中国模型的七个场景要求实际求解成功和独立验证有效。`services/hydraulics/tests/test_china.py` 检查来源哈希、拓扑、故障与隔离映射、不存在水泵时拒绝泵工况，以及证据许可被修改后拒绝读取。API 的实际运行回归包含中国模型。前端需通过构建和工作台默认数据源、新建任务选择的浏览器检查。

2026-10-06 本机验证：七个中国工况均求解成功且独立验证有效；水力回归 70 项（68 通过、2 项平台条件跳过）、任务 API 五项、契约 19 项、前端两项工作流检查及生产构建通过。启动脚本检查确认四个只读数据服务和任务 API 就绪。浏览器确认默认数据源、中国模型拓扑、正常/故障工况对照、来源与证据，以及新建任务默认中国网络和 164 条故障管段。

原始模型正常工况仍有约 1,102.9 m³ 的评估窗口缺供。按旧 20 m / 95% 阈值验收时全部节点低压；按新自适应相对判据，无故障基线通过，断裂与区域隔离仍有不满足阈值的节点。两种结果采用不同的验收要求，不能相互宣称工程达标改善。源模型管径、需求、水源水头与仿真结果未为消除违规而调整。

本次阈值更新验证：水力阈值与工作台 API 共 8 项测试通过；新增的自动/手动结果数值等价检查采用项目 Replay 容差（绝对 1e-10、相对 1e-12）并重跑通过。契约 19 项、契约检查、前端工作流 2 项和生产构建通过。七个默认场景均实际重算成功：正常、关闭、泄漏满足相对阈值，断裂、隔离未满足。浏览器确认手动提交、自动切回、工作台图例/曲线/违规列表同步，以及默认中国场景使用自适应阈值。
