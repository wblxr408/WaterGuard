# 前后端启动与接入

2026-10-05：WaterGuard 仅保留 `apps/web-gpt` 新版。工作台在 5173，任务 API 在 8010；旧 HTML 工作台和早期 React 原型已移除。

## 启动

Windows 启动脚本使用 PowerShell 7（`pwsh`）。新环境先安装 Python 和前端依赖：

```powershell
cd D:\WaterGuard
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r services/api/requirements.txt -r services/hydraulics/requirements.txt
npm ci --prefix apps/web-gpt
npm run start:web
```

也可双击 `scripts/start_waterguard.cmd`。启动脚本解压已有计算证据，复用或启动 8000 Fixture、8001 Benchmark、8002 A/B 只读服务、8010 任务 API 和 5173 Vite。关闭按 Ctrl+C，只清理自己启动的服务。

打开 [工作台](http://127.0.0.1:5173/)，[接口文档](http://127.0.0.1:8010/docs) 和 [健康检查](http://127.0.0.1:8010/healthz)。访问 API 根路径会跳到唯一的新版，`?run=<run_id>` 保留。其他前端部署地址可用 API 环境变量 `WG_FRONTEND_URL` 配置。

单独启动 API 用 `npm run start:api`，默认 8010。自定义端口例如 `npm run start:api -- 8011`，并在 `apps/web-gpt/.env.local` 设置 `WATERGUARD_API_URL=http://127.0.0.1:8011` 后重启 Vite；原生插件的 API 地址也需同步。开发 API 重载会中断活动计算，查看结果时无需重启服务。

Live 还需另开终端运行 `npm start`，启动官方 AGH 基座；见 [AGH 基座与启动](AGH基座与启动.md)。它复用或启动 8010 API，不提供第二套 WaterGuard 页面。

## 页面操作

1. 进入“智能体”，点击“新建任务”，选择 Net1/Net3 与正常、关闭、泄漏、断裂或隔离工况。
2. 选择真实目录中的故障管段，填写用户节点压力、供需比阈值和最多仿真次数（含基线，1–6 次）。
3. 选择 Benchmark 或 Live 并点击“创建任务并运行”。任务在服务端冻结，页面自动选择新运行并订阅工作流与 Info log。
4. 在分支导图、流程总览、节点详情和事件追踪中查看实际调用、候选和验收；运行中的“取消当前运行”会传递取消信号。
5. “模型账号”默认赛事 Agnes，通过官方 AGH 配置服务测试连接、读取目录、选择模型和保存。凭据只在本机输入。已有运行的模型不会因此切换。
6. 运行选择器读取服务端记录，`?run=<run_id>` 可直接恢复指定运行。人工 Fixture 必须显式切换来源。

应急工作台、方案对照、建模与仿真、证据中心继续读取标明来源的真实交付数据。当前新任务的结果在智能体节点详情中查看。

默认任务设置：0–3 小时仿真，0–1 小时预热，1–2 小时故障，1–3 小时评估；报告步长 900 s，水力内部步长 300 s。区域隔离采用目录中已定义的边界，泄漏面积为预设 0.0005 m²，流量系数 0.75。全部参数、来源假设和哈希以冻结任务为准。

## 接口与执行边界

| 接口 | 用途 |
|---|---|
| `GET /` | 重定向至唯一前端，保留查询参数 |
| `GET /api/networks/{id}` | 源模型拓扑、目录、可故障管段 |
| `POST /api/tasks/from-proposal` | 服务端冻结并保存 TaskSpec |
| `GET /api/tasks/{id}` | 冻结任务版本 |
| `POST /api/tasks/{id}/runs` | 创建实际运行 |
| `GET /api/runs`、`/api/runs/{id}/results` | 运行、候选、仿真摘要与独立验收 |
| `GET /api/runs/{id}/stream` | 持续推送 workflow、info、run，Last-Event-ID 续读 |
| `GET /api/runs/{id}/events` | 有限批次的历史事件 |
| `GET /api/runs/{id}/error` | 实际失败原因 |
| `POST /api/runs/{id}/cancel` | 取消信号传递到执行器 |
| `GET /api/agh/status`、`POST /api/agh/models/test`、`/save` | 实际模型配置状态、测试与保存 |
| `GET /api/runs/{id}/evidence`、`/evidence.zip` | 证据清单与文件包 |

Benchmark 固定枚举零动作及单动作候选，不承诺改善或穷尽搜索。计算完成仅表示执行结束；扰动复验仍可能 pending，正式推荐严格读取独立报告。提交候选的仿真完成后，SSE 等待该候选的独立验收送达再关闭。

Live 通过官方 SDK 接入 AGH 会话，缺少有效账号返回 `503 MODEL_NOT_CONFIGURED`，daemon 不可用返回 `503 AGH_UNAVAILABLE`。七工具的直接本地验收属于 Benchmark，真实模型闭环还需有效凭据验收。

执行器支持两个并发 Benchmark，SQLite 保留状态。异常重启后未结束的 Benchmark 记为 ERROR / SERVER_RESTARTED，需创建新运行。此版本使用单 API 进程，不能用多个 worker 同时管理相同数据库的执行任务。

## 验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s services/api/tests -v
npm run build --prefix apps/web-gpt
npm run test:workflow --prefix apps/web-gpt
pwsh -File apps/web-gpt/scripts/start-demo.ps1 -CheckOnly
```

API 回归覆盖真实水力计算、证据、幂等启动、取消、服务器冻结哈希和 SSE 迟到验收。浏览器核对新版的创建运行、自动订阅、模型配置入口和旧根地址重定向。
