# 仿真工程可靠性审查

审查对象：同学 1 仿真模块，初版提交 `05ef5d5`；日期：2026-10-03。判断依据是代码路径、真实引擎结果、边界故障注入和跨平台 CI，不以文件数量或测试数量代替结论。

**初版属于具备真实物理验收的工程原型，尚不接近可直接承担工业运行的完整系统。** 它已有固定来源、明确物理模型、独立进程、版本绑定、物理检查和证据回放，但 worker 信任边界、写入完整性与异常清理存在实质缺口。本轮已在仿真组件内修复这些问题；正式供水决策仍需现场模型与生产运行系统验收。

## 本轮发现与修复

| 严重性 | 原问题及影响 | 当前处理与证据 |
|---|---|---|
| 高 | worker 退出码为 0 且存在 result.json 就被接受；截断、错误绑定或伪成功可能穿过父进程 | `integrity.validate_output()` 复核 Schema、任务/方案/引擎/输入/时轴/实体覆盖、收敛、物理检查、原始文件及 sidecar 一致性；不合格结果隔离为 `rejected-worker-result.json`，返回协议失败 |
| 高 | 直接覆盖 JSON；异常中断可能破坏原文档，读者可看到半文件 | 同目录临时文件、flush/fsync、原子替换；替换失败测试确认旧文档完整且临时文件被清理 |
| 高 | 监督逻辑异常或 KeyboardInterrupt 可能越过正常取消分支，留下工作进程 | `finally` 收尾，terminate→wait→kill→wait；异常和中断分别留证，中断继续向调用方传播；注入实际进程退出与监督异常测试 |
| 中 | 输入身份只包含 WNTR 版本及项目代码，同版本其他数值依赖变化未必被发现 | 绑定 Python、OS/架构、数值包版本以及 EPANET/AML/隔离计算原生二进制 SHA-256；worker 再核对冻结环境/输入，回放环境变化即拒绝同版本声明 |
| 中 | 读取时未核对文件哈希；产物被修改后仍可能展示成原始结果 | `get_series()` 校验完整清单及哈希，再验证结果协议；清单 entries 与 hashes 双向一致，拒绝重复引用和符号链接 |
| 中 | wall-time 以外未限制产物或预期结果规模；无限 timeout 参数处理不明确 | `ExecutionLimits` 默认 256 MiB 产物上限、200 万估算结果值；持续检测超限并结束 worker；预先限制结果规模；NaN/Inf/非正 timeout 拒绝 |
| 中 | 仅有最终结果，进程阶段难以诊断 | 原子记录 `lifecycle.json` 的 PREPARING/RUNNING/终态、时间和 PID，并在进程退出后封存 execution 和清单 |

这属于失效安全处理：异常不会被解释成有效水力结果；原始引擎数据保留，不用填值或重新贴标签绕过失败。

失败结果的 `series` 和 `series_ref` 均为 null；worker 原始 CSV 和被拒绝结果仍保留供诊断。若 worker 改坏请求/输入锚点，先把原字节隔离为 `rejected-worker-*`，再恢复父进程冻结输入来生成失败记录，不能依据坏请求贴上成功标签。

EPANET 原生结果为 float32。本次 CSV 使用 17 位有效数字保留原值，父进程按原生类型复原后检查；WNTR 保留 float64。编译模型的源名称含绝对文件路径，校验文件名和全部物理字段，允许仓库根目录迁移，不把机器目录当作物理参数。

WNTR 对孤立节点把水头、压力、供水与漏损均输出为零。这种引擎约定只在父进程根据每个原始时间点的开启管段拓扑，确认该节点与所有水池/水库断开时接受，同时要求所有相邻管段流量为零。与水源仍连通的零流量节点继续检查 `head-pressure=elevation`；不能用孤立节点标签跳过物理校验。Net1/Net3 的真实隔离验收及连接状态/供水/漏损/流量篡改测试覆盖这一区别。

平台覆盖须如实区分：本机 Windows 无创建符号链接的权限，真实 manifest 链接测试交由 Linux CI；POSIX 忽略 SIGTERM 的测试也只在 Linux 运行，Windows 直接终止路径由真实进程回收测试覆盖。详细执行结果见 [测试报告](../benchmarks/student1/TEST-REPORT.md)。

## 保留的物理与复现约束

四种故障各有映射，泄漏不并入用户供水，隔离区域的需求不从分母删除，候选共享任务及预热条件但不共享可变网络状态。程序检查质量守恒与孔口公式，两引擎在共同支持工况下作数值比较。源控制必须完整确认，不能为了某个候选“成功”偷偷改变控制或阈值。

模型计算精度仍受 PDD、故障面积、系数和报告步长约束。WNTR 与 EPANET 的功能范围有差别，泄漏/断裂使用已验收的 WNTR 映射，不静默切换引擎。[WNTR 官方水力说明](https://usepa.github.io/WNTR/hydraulics.html)

进程超时后必须结束并回收子进程；创建进程本身在部分平台不能立即中断，因此本组件提供执行预算与清理行为，不声称操作系统级实时调度。[Python subprocess 文档](https://docs.python.org/3/library/subprocess.html)

JSON 原子替换防止读到半文件；这不等于多文件事务或断电零丢失。消费者以完整 evidence manifest 校验成功作为产物可用条件，不能只看到 lifecycle=SUCCEEDED 就使用数据。[Python os.replace 文档](https://docs.python.org/3/library/os.html#os.replace)

| 差距 | 为什么不能由当前验收替代 | 所属工作 |
|---|---|---|
| 现场模型校准与设施可操作性确认 | EPA 示例和声明假设没有证明当地需求、阀门位置、泵边界及遥测准确 | 同学 1 扩展数据/物理验收，需实际数据方输入 |
