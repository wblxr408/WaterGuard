# WaterGuard 后端设计

版本：0.2；日期：2026-10-02；状态：待实施。本文定义 API、AGH 宿主接入、工具网关、水力仿真、数据契约与证据存储。配套：[Agent 设计](Agent设计.md)、[前端设计](前端设计.md)。

实现更新：同学 1 的 [PhysicalAdapter 与 0.4 契约](同学1交付与复现.md) 已提供真实独立进程计算、四种故障、泵/管段动作、取消/超时和证据回放。当前 Agent 作业入口仍使用早期适配器，后端应统一复用可靠入口；本文其余内容继续作为 AGH、作业治理与产品 API 的实施设计。2026-10-04 的贯通缺口与实测结果见 [Agent 设计审查](Agent设计审查-2026-10-04.md)。

## 1 架构边界

AGH 中的 Agnes 负责核心规划、工具调用和反馈决策。后端是任务入口、运行宿主、确定性计算和治理设施。不能由 FastAPI 后台任务组织一套完整自主决策循环，再让 AGH 仅做解释。

前端只提交任务、修订、取消和读取请求，不直接调用仿真工具或模型。正式运行的核心工具请求必须绑定已核验的 AGH 会话来源。这个来源由宿主建立，不能靠模型填写一个 session_id 通过检查。

~~~mermaid
flowchart LR
    WEB["Web 前端"] --> API["FastAPI"]
    API --> HOST["AGH 会话宿主"]
    HOST --> AGH["AGH + Agnes 核心执行"]
    AGH --> GW["MCP/官方扩展工具网关"]
    GW --> POLICY["权限、版本、预算、参数检查"]
    POLICY --> WORK["独立计算进程"]
    WORK --> HYD["WNTR 水力引擎"]
    WORK --> VERIFY["独立程序验证"]
    HYD --> STORE["产物与索引"]
    VERIFY --> STORE
    STORE --> GW
    GW --> AGH
    STORE --> EVENTS["事件投影"]
    HOST --> EVENTS
    EVENTS --> WEB
~~~

MCP 是优先核验的集成候选，不假设赛事版 AGH 已支持本文接口。具体官方协议、版本和调用方式由接入探针锁定。

## 2 模块与技术选择

| 模块 | 职责 | 禁止越界 |
|---|---|---|
| api | 任务、运行、查询、修订、导出、SSE | 不直接调用 LLM 或驱动候选决策 |
| agh_host | 启动、恢复、取消 AGH，加载限定配置、收集原生日志 | 不伪造 AGH 会话，不内嵌替代智能体 |
| tool_gateway | 暴露项目工具，认证角色和运行，验证参数 | 不接受模型自报权限 |
| policy | 版本、能力、预算、推荐准入 | 不降低任务硬约束 |
| candidate_generation | 有限动作域的图分析、规则/枚举候选 | 不隐藏模型调用或完整反馈循环 |
| hydraulics | 网络载入、故障与动作编译、计算、原始输出 | 不选择业务目标或编造模型参数来源 |
| verifier | 数据有效性、约束和指标复算 | 不依赖模型自评 |
| evidence | 文件哈希、来源、关联索引、脱敏和导出 | 不将应用事件称为原生 AGH 日志 |

建议 Python、FastAPI，水力计算在独立进程运行。首版单 API 与持久作业队列足够。SQLite 存元数据、状态和预算账本，JSONL 存不可变事件副本，Parquet/JSON 存时序。并发写入由单写入器或短事务控制；正式多用户扩展后再迁移数据库。

Python 及依赖版本通过 AGH/MCP 与 WNTR 兼容性测试后锁定。扩展与仿真需要不同 Python 版本时拆成两个进程环境，通过结构化契约通信，不能直接照搬某篇教程的版本要求。

## 4 公共数据契约

本节为跨三份设计文档的字段与状态设计依据。2026-10-02 已在 [packages/contracts](../packages/contracts/README.md) 实现开发契约，当前 0.2.0 兼容 day1 的 0.1.0 Fixture，并支持正常工况 fault=null；已冻结字段以其中的 JSON Schema 为准。它们是项目内部契约，AGH 原生字段另存并映射。

| 对象 | 必备字段 | 不变量 |
|---|---|---|
| NetworkManifest | network_id、revision、sha256、source_url、license、units、coordinate_system、overlays | 原文件不可变，附加层有独立来源 |
| TaskSpec | task_id、revision、network_ref、fault、time_window、objectives、hard_constraints、soft_preferences、action_catalog_ref、perturbation_domain、assumptions、budget、constraint_hash | 冻结后只读 |
| ActionPlan | candidate_id、task_ref、parent_candidate_id?、actions、source、plan_hash | 动作引用合法设施；无结论数值 |
| SimulationArtifact | simulation_id、candidate_id、perturbation_id?、engine_version、input_hash、status、series_ref、diagnostics_ref、time_axis | 输入、引擎、时序可复现 |
| VerificationReport | verification_id、simulation_id、validity、violations、metrics、coverage、verifier_version | 只由验证器写入 |
| DecisionRecord | decision_id、agh_session_id、role、input_refs、summary、next_action_ref | 引用真实输入，理由简短 |
| RunRecord | run_id、task_ref、mode、status、phase、agh_session_ref、model_config_ref、budget_usage、conclusion | 流程状态不等于工程通过 |
| EvidenceManifest | bundle_id、run_id、native_trace_ref、association_ref、artifacts、hashes、redactions、missing_items | 缺项可见，不伪装完整 |

task_ref 包含 task_id、revision、network_hash、constraint_hash。单位统一为 SI：长度/水头/压力水头用 m，流量用 m³/s，时间用 s。用户输入和展示单位可转换，但内部计算和来源均保留。

运行模式为 live、replay、fixture、benchmark。fixture 设计数据永远不能作为 live 证据导出。replay 读取已经存在的运行，不生成新的 AGH 调用记录。

### 4.1 状态与阶段

运行状态枚举：

~~~text
QUEUED | RUNNING | NEEDS_INPUT | COMPLETED
| BUDGET_EXHAUSTED | ERROR | CANCELLED
~~~

运行阶段：

~~~text
INTAKE → MODELING → BASELINE → PLANNING
→ SIMULATING → VERIFYING → REVIEWING → PACKAGING
~~~

PLANNING、SIMULATING、VERIFYING 可按 AGH 的真实决策反复出现。后端只验证合法状态转换和执行生命周期。

conclusion 单独保存 FEASIBLE_FOUND、NO_FEASIBLE_FOUND、INCOMPLETE 或 INVALID。候选又有 action_valid、simulation_valid、nominal_constraints_pass、required_stress_tests_pass、recommendation_eligible 五项。COMPLETED 只表示流程结束，不等于找到可行解。

## 5 HTTP 与事件接口

所有命令校验用户身份、任务访问权限和输入 schema；开发单机版可限定 localhost，后续共享部署才启用相应认证。正式多用户部署不能沿用未鉴权开发入口。

| 接口 | 行为 | 返回 |
|---|---|---|
| GET /api/networks | 读取可用网络及来源 | 网络摘要列表 |
| GET /api/networks/{id}/scene | 读取渲染数据与设施映射 | 坐标、连接、属性、资产引用 |
| POST /api/tasks | 保存用户需求和场景草案 | task_id、revision |
| POST /api/tasks/{id}/runs | 启动 AGH 核心会话 | run_id、mode=live、初始状态 |
| POST /api/runs/{id}/answers | 提交当前澄清问题的答案，恢复 AGH | 接受结果或过期请求错误 |
| POST /api/tasks/{id}/revisions | 用户修改条件，建立新版本 | 新 revision，不覆盖旧记录 |
| POST /api/runs/{id}/cancel | 幂等取消宿主及计算 | 状态与已保存产物 |
| GET /api/runs/{id} | 运行、阶段、预算、结论 | RunRecord |
| GET /api/runs/{id}/events | SSE；支持 Last-Event-ID | 增量 RunEvent |
| GET /api/runs/{id}/candidates | 同任务版本候选 | 指标、状态、证据引用 |
| GET /api/simulations/{id}/series | 按设施与时间范围读时序 | 原始或显式降采样数据 |
| GET /api/runs/{id}/evidence | 读取已生成证据包索引 | 完整性、来源及下载引用 |

不存在浏览器可调用的任意 simulate 或模型代理接口。工具调用走已授权 AGH→网关路径；开发测试入口必须与正式运行隔离并标记 benchmark。

事件最小字段：

~~~json
{
  "event_id": "evt_example",
  "sequence": 42,
  "run_id": "run_example",
  "task_revision": 1,
  "constraint_hash": "sha256:example",
  "agh_session_ref": "native-session-or-mapped-reference",
  "native_tool_call_ref": null,
  "correlation_id": "corr_example",
  "origin": "gateway",
  "type": "verification.completed",
  "candidate_id": "candidate_example",
  "simulation_id": "simulation_example",
  "occurred_at": "2026-10-02T08:00:00Z",
  "simulation_time_s": null,
  "payload_ref": "artifact:verification_example"
}
~~~

示例不是实际运行。origin 区分 agh、gateway、worker、verifier、user；缺失原生字段保留 null 和原因，不能补造成原生证据。SSE 使用单调序号，客户端去重；日志截断或恢复间隙要明确报告。

## 6 工具网关与执行身份

工具清单以 [Agent 设计第 6 节](Agent设计.md#6-工具契约与角色权限) 为准。每个工具先验证会话、角色、任务版本、能力、预算，再读取产物或派工。

宿主提供受限凭证或可信的角色绑定。凭证不放入提示词、浏览器或公开日志。不能仅检查请求参数是否写着 agh=true。工具服务只能访问对应任务目录和运行资产；允许的动作和网络资源由服务器解析。

候选生成工具只产生有限动作候选及诊断。它可以使用图分析、约束枚举或启发式，不把业务反思循环藏在内部。仿真由 AGH 显式请求，长计算返回句柄，之后通过 wg_get_simulation 获取结果；轮询采用退避或受支持的通知方式，避免空转。

wg_build_evidence 可在无解、取消前已完成部分等情形构建失败证据。selected_candidate_id 可为空；传入候选不等于推荐成功，网关独立检查准入条件。

## 7 水力模型与动作编译

### 7.1 数据准备

从公开小网络调试，再选择较大网络展示。保存原始 INP、下载来源、许可、哈希和版本。检查网络是否能正常计算、单位、需求模式、时间步长、水箱初始水位与控制规则。

医院等关键节点、阀门布局、埋深和场景需求可能不是公开模型自带属性。此类数据放在单独 overlay 中，标注 assumed、synthetic 或 measured，不能覆盖原始来源。

### 7.2 故障与边界条件

区分泄漏、完全断裂、管道关闭、隔离区切断。不能用“关闭管道”冒充所有爆管物理过程。每种故障明确水力映射、作用时刻和持续时间，必要时按引擎能力拆管并添加泄漏节点。

低压缺供采用压力相关需求计算。最低压力、满足需求压力、指数等参数须记录，不能直接将默认值当作真实城市标准。

所有候选从同一原始模型、相同预热和故障时间线构造独立实例；保留动态水箱状态连续性，不在每次动作时重新初始化系统。参数变化生成新场景，禁止候选间共享可变网络对象。

### 7.3 合法操作

首版优先支持模型中明确存在的 link_open/link_close，以及经过验证的 pump_on/pump_off。调速和调压只在对应曲线、设备范围及引擎行为均有依据时加入。

隔离阀图层用于分区分析，不自动等价于水力阀门对象。为图层设施建立到 link 或实际阀件的编译关系，检查哪些用户会被隔离。拓扑图中的视觉交叉不产生连接；不能为了美观增加计算边。

计划中的动作按 simulation_time_s 执行，检查互相矛盾的状态、过短切换、操作上限、设施可用性及前置条件。不能无条件覆盖原网络已有控制；冲突要明确处理。

## 8 指标与验证器

对用户节点 i、时段 k，定义期望需求 d(i,k)、实际用户供水 q(i,k)、步长 Δt(k)。泄漏量单独统计，不能并入用户用水。

~~~text
累计缺供体积 = Σ max(d − q, 0) × Δt
供需体积比 = Σ min(max(q, 0), d) × Δt / Σ d × Δt
关键节点达标率 = 满足配置要求的节点时长 / 总受评节点时长
操作成本 = Σ 已明确配置的动作成本
~~~

比值只对有效、非负的用户需求定义；总需求为零时返回不适用。隔离后的用户需求仍计入分母和缺供。负值、缺帧、NaN、未收敛要触发有效性检查，不能靠公式截断掩盖引擎错误。公式中的限幅用于有物理依据的统计约定，异常仍单独上报。

验证器从原始时序重新计算指标，检查每个硬约束的节点、时段、阈值和容差。硬约束先检查，可行候选再按显式目标或 Pareto 比较，不让加权总分掩盖违规。

推荐准入同时要求任务版本一致、动作合法、计算有效、名义硬约束满足、必要复验完成、证据齐全。模型自评信心不参与放行。独立验证模块共享同一引擎结果，仍不能声称独立物理实证；小案例采用解析/守恒检查，适用时增加另一引擎交叉比较，并说明共有假设。

## 9 存储与证据

~~~text
artifacts/{run_id}/
  task.json
  network_manifest.json
  runtime_config.redacted.json
  agh/native/                  原始导出或授权脱敏副本
  agh/association.json          原生记录与应用记录映射
  events.jsonl
  candidates/{candidate_id}/plan.json
  simulations/{simulation_id}/input_manifest.json
  simulations/{simulation_id}/series.parquet
  simulations/{simulation_id}/diagnostics.json
  verifications/{verification_id}.json
  report.json
  evidence_manifest.json
~~~

数据库保存任务、运行、会话、候选、计算、验证、事件索引及预算账本。结果先写临时文件，完成校验后原子发布；证据包记录内容哈希。哈希用于一致性核查，不等于独立来源认证。

缓存键必须包含原始网络与 overlay、完整任务、动作、扰动、引擎和验证器版本、时间轴等会影响结果的输入。命中缓存显式记录来源，不冒充新算出的结果；性能评测区分冷启动和缓存运行。

## 10 预算、并发、幂等与异常

队列派工前在事务中预留仿真额度和并发槽位，实际失败尝试也记账。多个 Agent 不能各持独立无限预算。模型调用与费用从实际可取得的提供商/AGH 记录导入，缺失计量标为未知，不推算成精确值。

幂等键由可信调用关联与规范化请求计算。重复 HTTP/SSE 不重复派工；如果 AGH 明确要求重新试验，生成新请求并登记原因。取消和任务修订使运行能力失效，迟到结果只进入历史记录。

| 错误码 | 含义 | 后续 |
|---|---|---|
| AGH_UNAVAILABLE | 宿主或会话不可用 | 正式运行停止，不切外部模型 |
| MODEL_NOT_ALLOWED | 模型配置超出允许列表 | 阻止启动 |
| INPUT_INVALID | 输入、单位或引用非法 | 返回字段级问题 |
| INVALID_ACTION | 动作不在合法域 | 交回 AGH 修正 |
| PERMISSION_DENIED | 角色无此能力 | 拒绝并记录 |
| TASK_REVISION_MISMATCH | 使用旧任务版本 | 终止当前请求 |
| SIMULATION_FAILED | 计算错误或不收敛 | 标记无效，保留诊断 |
| TOOL_TIMEOUT | 计算超过配置时限 | 终止进程并回报 |
| ARTIFACT_INVALID | 结果缺失或不一致 | 不进入推荐区 |
| BUDGET_EXHAUSTED | 资源上限到达 | 保存现有结果并结束 |
| ELIGIBILITY_INCOMPLETE | 复验或证据不完整 | 限定结论，不推荐 |

约束违反属于有效计算后的业务结果，不等同于计算异常。NO_FEASIBLE_FOUND 表示已搜索范围内未找到，不表示数学证明无解。

## 11 验证计划

- 契约：无效参数、单位转换、旧版本、未知设施和角色伪造被拒绝。
- 物理：正常基线、泄漏与关闭差异、控制冲突、相同时间线、独立候选状态。
- 指标：漏水与用户供水分离、隔离节点缺供、零需求和缺失结果。
- 系统：取消、超时、队列恢复、SSE 续读、重复请求、并发预算。
- AGH：真实工具调用与原生记录关联，反馈驱动修正，错误不触发其他模型。
- 端到端：任务进入 AGH，真实水力结果返回前端，证据可以复算。

文档验收不等于上述测试已经通过。实现后用实际产物填充记录；低影响文案修改无需建立镜像式测试。
