# WaterGuard · 水脉卫士

面向供水管网突发故障的应急调度、仿真验证与决策证据工作台。

## 当前状态

项目处于架构与交互设计阶段。目前已有可交互的产品蓝图，尚未接入 Agnes、AGH 或真实水力仿真。蓝图中的拓扑、读数及运行记录均为明确标注的示意数据。

- [产品与架构蓝图](design/waterguard-blueprint.html)
- 蓝图包括应急工作台、方案与证据、Agent 架构、边界治理、评测与实施五个页面。
- 下载后用浏览器打开 HTML 即可预览，无需安装依赖。

## 产品任务

在已知爆管位置、允许操作的设施和保供要求下，生成、比较并验证应急处置方案。展示故障影响、候选动作、验证失败原因、修正过程及结论的适用范围。

## 建议架构

三个专业 Agent：任务建模、方案规划、反例审查。确定性的运行控制器负责权限、状态、预算和版本；水力仿真与程序校验提供结果依据。

- 前端：React、TypeScript，管网、指标与证据联动。
- 后端：Python、FastAPI、持久任务队列和独立计算进程。
- 水力仿真：WNTR / EPANET；使用公开网络模型。
- 运行底座：按赛事要求接入 AGH 和 Agnes，具体接口与版本待验证。

以上为设计提案，尚未实现或完成技术验证。

## 边界治理

- 冻结任务目标、硬约束、软偏好及版本；Agent 不得自行降低保供要求。
- 从明确的设施与动作目录生成方案，校验物理映射、参数及前置条件。
- 运行产物绑定输入和约束版本，旧结果不能覆盖新任务。
- Agent 不能写入验证通过结论；数值和状态来自原始结果与程序检查。
- 分别呈现动作合法、仿真有效、名义工况达标和指定扰动复验状态。
- 设置模型、仿真和时间预算，保留失败与取消的记录。

## 实施顺序

1. 核验赛事 AGH 接入与证据导出；复现公开管网的正常及故障基线。
2. 建立合法动作映射、指标计算、固定搜索与独立验证。
3. 接入规划 Agent 和真实前端，完成失败、修正、复验闭环。
4. 增加任务建模和反例审查，以相同预算对比固定搜索、单 Agent 与多 Agent。
5. 完成留出场景评测、证据包、演示与复现说明。
