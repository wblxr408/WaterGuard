01
任务建模 Agent
将用户要求转成有来源、有类型的任务提案。
  • 识别目标、硬约束、软偏好和未知项。
  • 读取网络目录与设施能力。
  • 输出 TaskSpec 提案与歧义标记。
  • 没有修改已冻结约束或运行仿真的权限。
输入：需求 + 网络摘要
02
方案规划 Agent
根据真实反馈调整候选动作与搜索范围。
  • 从合法动作集合提出 ActionPlan。
  • 请求有预算的候选搜索与仿真。
  • 读取失败证据，修正方案。
  • 不能写验证结果、改阈值或声明推荐通过。
输入：任务快照 + 工具结果
03
反例审查 Agent
查找候选的薄弱条件，提出有针对性的复验。
  • 检查未证实的假设和遗漏工况。
  • 输出 StressTestRequest 与证据引用。
  • 可请求受限的扰动测试。
  • 不改候选、不改原任务，不拥有最终放行权。
输入：候选 + 验证摘要


前期先跑通“任务模板 → 规划 Agent → 仿真 → 程序校验”，再增加任务建模与反例审查。用实验决定多 Agent 是否保留；角色数不是创新指标。

GOVERNANCE / ENFORCEABLE BOUNDARIES
边界由代码执行，证据决定能否通过。
将物理、目标、权限、状态、资源与结论的边界写进接口和状态机。
设计约束




边界强制机制违反后行为前端表现


目标与约束TaskSpec 冻结；目标、硬约束、软偏好分离；参数记录来源；约束哈希绑定所有结果拒绝 Agent 直接修改阈值。确需改变时生成任务修订提案，由用户决定显示阈值来源、版本、变更差异；旧结果标记失效


动作与物理设施白名单；关闭管道、隔离阀层、泵启停分别映射；操作时间及前置条件校验未知设备、不可达动作、超界设置在仿真前被拒绝在动作列表定位被拒项并解释原因


角色权限工具网关验证角色能力；权限由服务端运行身份决定，不能接受模型自报角色返回 permission_denied，记录审计事件显示被阻止的越权提案，不显示为已执行动作


数据与指令INP、备注和工具输出视为数据；不允许其中的文本覆盖任务规则；无运行时任意代码工具结构非法则拒绝；模型提议仍需过权限与参数检查标记数据问题与可修复字段


结果与证据报告字段来自运行产物；校验器独立模块，读取原始时序；Agent 不得写“通过”字段缺产物、哈希不一致、无效数值或未收敛，不进入推荐区区分合法、仿真有效、名义达标、扰动复验


资源与停止模型轮次、模拟次数、墙钟时间、并发与 Token 上限由控制器执行预算结束返回最佳已验证候选或“未找到”；取消终止子进程显示真实消耗、结束原因与结果完整程度


并发与版本不可变任务快照；候选独立进程；幂等键；任务版本与数据哈希检查重复事件去重；旧运行归档；过期结果不覆盖当前任务历史与当前任务分开，更新输入后显示待重验


结论范围分别记录求解状态、约束满足与覆盖的工况；报告不能超出证据“预算内未找到”不升级为“无解”；模拟有效不升级为现场适用显示覆盖范围和未覆盖条件；无虚构可靠率

物理边界必须明确
采用压力相关需求模型评估缺供。统一内部单位，并保持所有候选的初始状态和需求时间轴一致。泄漏量与用户供水量分别统计。
公开网络缺少医院、阀门位置等信息时，附加层显式标为场景假设。图层中的隔离阀不会自动改变水力模型，需编译成对应操作并校验。
本期以延时水力仿真为范围；不从这些结果推断水锤、水质或真实控制系统的执行效果。
审查不等于另一张通过票
审查 Agent 可以发现疑点并要求复验；通过结论仍来自程序检查。使用同一模型的多个角色可能产生相同错误，不能把一致意见当作独立验证。
校验器读取原始结果并重新计算指标，但共享同一物理引擎的结果仍属于同一模型假设下的证据。
已知错误由规则拦截，开放性的缺失假设由审查 Agent 发现，两者互补。


首版建议预算与失败协议
起始预算建议：每任务最多 4 轮修正，最多 40 次候选仿真（含扰动测试），2 个并发计算进程；单次及总超时先实测后配置。这些是起始参数，不是性能承诺。模型输出格式错误最多修复 1 次；工具临时故障只按确定性策略重试；超预算、取消、未收敛、输入错误、无可行候选分别归类。审查服务失效时只能展示基础验证状态，不能标记完成审查。暂停、取消和重跑都保留已完成证据。

实验组配置回答的问题
规则基线固定处置规则 + 相同仿真器优化处置是否改善供水？
固定搜索相同动作域、仿真预算与验证器，无 LLMAgent 相对固定搜索有什么增益？
单 Agent一个规划角色承担解释与修正，同样治理层单 Agent 能否完成任务？
多 Agent任务建模 + 规划 + 反例审查，同样总预算角色隔离是否降低错误并提高完成率？


多 Agent 保留标准：在相同总模型预算、仿真次数与墙钟上限下，比较合法任务率、约束满足率、未检出违规数、缺供量、延迟和费用。如果多 Agent 没有净收益，保留可选审查模式。


评测集与指标口径
建议从 Net1 调试，Net3 主展示，再加入另一公开网络检验迁移。初始测试清单为 30 个冻结场景：12 个常规故障、10 个边界工况、8 个失败与治理案例；另留至少 10 个不用于调提示词的场景。多网络、故障位置和需求模式按组留出；记录生成种子，避免同一案例的小扰动跨开发集与留出集。

累计缺供体积 = Σ节点 Σ时段 max(期望用户需求 − 实际用户供水, 0) × Δt
供需体积比   = Σ min(实际用户供水, 期望用户需求) × Δt
              / Σ 期望用户需求 × Δt
关键节点达标率 = 满足配置压力/供水要求的节点时长 / 总受评节点时长
操作成本 = Σ 显式动作成本；同时单列操作次数
稳健性 = 已测试扰动集合中的约束满足情况（不可外推为真实可靠率）
零需求节点不用于比值分母；隔离后其未满足的用户需求仍要计入缺供。泄漏另算。无效值、仿真不收敛或丢失时段不算通过。小型有限动作域可穷举参照；大规模问题只报告最佳已发现和预算。
